# Growth with AI：AI 學習階段地圖

很多人以為自己「未學識 AI」，其實不是因為未試過 ChatGPT、未看過 Prompt 教學，亦不是因為未追到最新工具。真正卡住的地方通常更貼近工作：AI 出到一段答案，但自己不知道可不可以交；每次開新對話都要重講背景；想交一件重複工作出去，卻發現做法只在自己腦裡；或者已經做過一個 Agent demo，但仍然說不清它究竟替誰創造了甚麼價值。

Growth with AI 是一個公開的廣東話 AI 實戰攻略 library。它不把 AI 當成一堆功能，也不把人分成「識」或「唔識」。這裡把學習拆成五個可來回走的工作階段：由完成第一件真工作、讓 AI 讀懂你的 context、交接重複流程、親手建立可靠的 AI 幫手，到帶團隊或客戶用 AI 改善一條真 workflow。每一篇攻略都想回答一個更實際的問題：**我現在卡在哪裡？下一步可以做甚麼？做完後應該留下甚麼？**

你不需要由第一篇順讀到最後一篇，更不用等自己「準備好」才開始。先找一個最像你現況的入口，讀一篇、做一個低風險練習，留下可 review 的成果；當下一次工作少猜了一步，你就已經在進步。

## 關於 Jimmy Lau

Jimmy Lau 是 DotAI 的 Founding Partner — AI Adoption & Education。Jimmy 關心的不是叫大家多開幾個 AI account，而是幫人把 AI 放回真實工作裡：由「它可否先幫我做好一件事」，慢慢走到「我能否把 context、標準、review 和責任講清楚」，再到「這條 workflow 是否真的幫到一個人、一個團隊或一項服務」。

這個 library 整理了 Jimmy 在教學、實踐和反思中反覆使用的工作判斷。它不是官方工具文件，也不是保證任何人會得到同樣成果；你仍要按自己的資料權限、工作責任、行業規則和人手 review 去判斷。不過，這裡會幫你把那些平時很難說清的 AI 工作習慣拆開：甚麼應先做、甚麼暫時不要做、甚麼值得留低給下次的自己、人手或 AI。

## 這裡有甚麼：五個 AI 學習階段

五個 Stage 不是職級、證書或必經次序。它是一張「你現在可以負責到哪一步」的地圖。同一個人可以在內容工作是 AI Operator、在 coding 是 AI User；你亦可以先讀 AI Builder 的某一篇，但當你發現 context 或驗收未清楚時，再回到前面補底。

| 階段 | 當你開始問這條問題 | 這一關真正要練的能力 | 你會留下甚麼 |
|---|---|---|---|
| [AI User（AI使用者）](<AI 學習階段地圖/01-AI User（AI使用者）/README.md>) | 「我可不可以先叫 AI 幫我做一件真工作？」 | 選一件低風險、自己驗收到的小任務；講清材料、完成線和不能碰的界線。 | 第一份可 review 的 AI 成果，以及一條基本驗收線。 |
| [AI Super User（AI熟練使用者）](<AI 學習階段地圖/02-AI Super User（AI熟練使用者）/README.md>) | 「點解 AI 每次都要我重新解釋？答案又未貼住我的標準？」 | 提供剛好夠用的 context、例子、證據與 feedback，讓下一次不用從零猜。 | context、任務包和 feedback rule。 |
| [AI Operator（AI工作操作者）](<AI 學習階段地圖/03-AI Operator（AI工作操作者）/README.md>) | 「呢件事我每星期都做，但交畀同事或 AI 就斷線。」 | 把在腦裡的工作攤開：現況、owner、步驟、例外、交接與更新節奏。 | work map、minimum SOP、現況記錄。 |
| [AI Builder（AI建立者）](<AI 學習階段地圖/04-AI Builder（AI建立者）/README.md>) | 「我想用 Codex、Skill、Agent 或 automation，但怎樣才不會亂猜或失控？」 | 把已看清的工作做成可試跑的系統：輸入、輸出、品質閘、human review 和停止線。 | AI work card、品質閘、試跑紀錄。 |
| [AI Value Creator（AI價值創造者）](<AI 學習階段地圖/05-AI Value Creator（AI價值創造者）/README.md>) | 「有 demo 之後，怎樣證明它真的值得保留、擴大或教人用？」 | 用一條真 workflow 跑安全 pilot，衡量質量、速度、風險與採用情況。 | pilot、value proof 和下一步決定。 |

這個排序的重點不是「升級」，而是責任範圍逐步變大。你一開始只需對一份草稿負責；之後開始對 context、交接和例外負責；再後面要對系統品質、團隊採用和真實成果負責。AI 愈能做事，人反而愈需要把判斷、責任和邊界說清楚。

## 由你現在的情況開始，而不是由工具開始

很多 AI 學習內容一開始就叫你揀 ChatGPT、Gemini、Claude、Codex 或某個最新 Agent。工具當然重要，但工具選擇往往不是第一個問題。若你連要交甚麼、誰會收貨、哪些資料不能交出去都未講清楚，換工具通常只會令你更快得到一個未必可用的答案。

你可以用以下路線找入口：

| 你而家最常遇到的情況 | 建議先讀 | 不用急著做甚麼 |
|---|---|---|
| 我只是想 AI 幫我做好一件電郵、整理、研究或初稿工作。 | [AI User](<AI 學習階段地圖/01-AI User（AI使用者）/README.md>) | 不用先學 code、API 或多 Agent。 |
| 我已有常用 AI 工具，但每次效果不穩、要反覆追問。 | [AI Super User](<AI 學習階段地圖/02-AI Super User（AI熟練使用者）/README.md>) | 不要一下把所有資料塞進去。 |
| 同一件事總是由同一個人記得怎樣做，AI 或同事一接手就亂。 | [AI Operator](<AI 學習階段地圖/03-AI Operator（AI工作操作者）/README.md>) | 不要先急著自動化整條流程。 |
| 我想用 Codex、Skill、Agent、Connector 或 automation 做出一個 AI 幫手。 | [AI Builder](<AI 學習階段地圖/04-AI Builder（AI建立者）/README.md>) | 不要把 demo 當成已可長期運作的系統。 |
| 我想帶團隊、開班、做顧問服務，或證明 AI 對業務有價值。 | [AI Value Creator](<AI 學習階段地圖/05-AI Value Creator（AI價值創造者）/README.md>) | 不要只用登入數或「大家話好用」做結論。 |

## AI Agent 不是第六關：它是一種工作交付方式

AI Agent 容易令人以為是「比聊天更高級」的工具，於是有人一開始就想建立 autonomous agent team。其實 Agent 講的是：你想讓 AI 協助處理哪一段工作；五個 Stage 講的是：你現在有沒有能力為這一段工作負責。兩者不應混在一起。

一個安全的 Agent 起點，可以是「活動後的 internal follow-up draft」：AI 只讀已批准的活動 brief 和 FAQ，先產生內部草稿，由人 review；不是一開始便讓它自行發信、改動 CRM 或承諾會省下多少成本。這個例子同時需要五種能力：揀對工作、交清 context、寫清交接、設品質閘，以及最後量度是否值得繼續。

| 當你想用 Agent 做甚麼 | 你要先判斷甚麼 | 最值得讀的 Stage |
|---|---|---|
| 試一試它可否幫到某件工作 | 這件事低風險嗎？我自己可否 review？ | AI User |
| 令它不要每次亂猜 | 我有沒有足夠而不過量的資料、例子和限制？ | AI Super User |
| 交一件重複工作給它處理 | 現況、owner、例外和交接可否被看懂？ | AI Operator |
| 親手建立第一個可靠 AI 幫手 | 輸出如何驗收？何時需要人接手或停止？ | AI Builder |
| 決定要不要擴大到團隊或客戶 | 它是否令 workflow 更快、更準、更安全或更容易採用？ | AI Value Creator |

## 每一關都在練的五個基本動作

無論你是在寫 Prompt、做內容、設計課程、用 Codex 寫程式，還是建立一個 Agent，底層其實都離不開以下五個動作。這些不是額外的理論，而是你每次用 AI 時都可以拿來檢查的工作習慣。

1. **問清工作**：這次到底要交甚麼？誰會收貨？何時才算完成？
2. **揀對材料**：哪些是可靠根據、哪些只是參考、哪些仍然未知或不應交給 AI？
3. **排好結構**：人或 AI 接手時，能否看懂現況、規則、例外和下一步？
4. **分配工具**：這一段應交給人、聊天工具、Skill、Agent，還是其實暫時不做？
5. **回收判斷**：今次改了甚麼、為何改、下次怎樣少猜一次？

AI 的價值往往不在於它一次過給你很長的答案，而在於你能不能把一次做得好的方法留下來。留下來的可以是一份 task pack、一條 review rule、一頁 SOP、一張 work card，或一個說清楚「做／不做」的決定。它們會令下次的工作不必由零開始。

## 這個 library 怎樣閱讀才有用

目前這裡有超過一百篇攻略與練習，並不是叫你當課本一次過讀完。較有用的閱讀方法是：先在每一關的 README 開始，揀最貼近現況的「先由這篇開始」；讀完後只做一個細小、安全、自己可驗收的練習；然後才按新出現的問題選下一篇。

當你看一篇文章時，可以用三條問題檢查它有沒有真正幫到你：

- 它有沒有說中我現時的工作摩擦，而不只是介紹工具？
- 我現在能否留下某樣看得見的東西，而不是只多知道一個術語？
- 它有沒有講清楚甚麼情況不應照抄、要由人做判斷？

如果答案是「未有」，不代表你不夠好；多數只是你跳得太快，應該回前一層補 context、SOP 或驗收線。這也是為甚麼這張地圖可以來回走。

## 公開內容的邊界

這個 repository 只放公開安全、可獨立閱讀的內容和 synthetic 例子。它不會放客戶資料、合約、CRM、付款、帳密、會議紀錄、production data 或私有 Vault；亦不會把一次 demo 包裝成已驗證的成果，或鼓勵你跳過權限、owner 和人手 review。

真正把 AI 放進工作時，請按你的公司規則、資料敏感度、行業要求和責任範圍再作決定。安全不是限制你使用 AI，而是讓你知道哪些地方可以放心試、哪些地方要先縮小、哪些地方必須由人留在最後一關。
