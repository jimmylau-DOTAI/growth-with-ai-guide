# 攻略

每頁教一件今日做得到嘅事。**唔使先搞清楚自己第幾關** —— 睇邊個症狀似你，就入邊頁。

---

## 出嚟嘅嘢唔啱用

你交咗嘢畀佢，佢做咗，但你要自己執一次先用得。

**[為甚麼 AI 總是順著你的邏輯答？因為你沒講的它會自己填 —— 一段反問指令，三個力度](ai-counter-question-before-answering.md)**

你一開口，佢已經開始答 —— 你冇講嘅嘢，佢會揀最常見嗰組填。呢頁畀你一段可以直接貼上去嘅指令。

・一段完整指令，四個部分逐個拆解點解要有
・兩個關鍵標明：一個令你知道值唔值得答，一個令你可以唔答
・邊類工作值得用（同邊類唔值得）
・兩個真實成本：佢會令你慢、佢救唔到你唔識嘅嘢

**[AI 生圖為甚麼總是不像你的產品？它看得見形狀，看不見產品 —— 四步法與八項理解報告](ai-understand-product-before-generating.md)**

佢睇得見形狀，睇唔見產品。寫幾長都改唔到，因為你補嘅係「點畫」，缺嘅係「呢件係咩」。

・**五種最常見嘅失敗**，逐個講底層原因（材質、部件、比例、賣點、調性）
・四步流程：理解 → 核對 → 寫指令 → 迭代
・理解報告嘅八項，逐項要檢查咩
・點解「你核對」嗰步唔可以慳

## 想令 AI 下次真係少猜一點

你唔係要將 prompt 寫到無限長，而係要先交代今次任務要做到乜、可以用邊啲材料、邊啲未知要停低，同埋咩叫合格。

**[跟住填：五格組一個 AI task pack](build-an-ai-task-pack.md)**

用 Task、Material、Examples、Boundary、Evaluation 五格，將一次真工作講得剛剛夠用。它不是叫你上載更多資料，而是令 AI 少補錯空白。

**[跟住整理：把一條 feedback 變成下次可用的判斷](turn-feedback-into-a-rule.md)**

不是每一句修改都要塞進 memory。這頁教你分清一次性 edit、重複 pattern 和 changed requirement，只留下有原因、範圍、owner 和 expiry 的 rule。

**[跟住填：一篇 source 點樣先變成你自己的工作判斷？](turn-a-source-into-your-own-decision.md)**

把 source 講了甚麼、你怎樣理解、下一次會改哪個做法和何時不適用分開寫；唔係把作者的話換成第一人稱。

## 每次都要由頭嚟過

同一啲嘢你講過好多次，但下次又要再講一次。

**[為甚麼每次開新對話都要重講背景？不是 AI 記性差，是分類問題 —— 記憶四層設定法](ai-memory-four-layers.md)**

唔係記性問題，係分類問題。四種唔同性質嘅資料塞晒入同一個位，放錯咗，記得住都冇用。

・四層分別放咩，逐層講清楚
・**呢四層喺你部工具入面實際叫咩**（網頁版 vs 工作台對照）
・三條問題，答完就知一件資料該放邊層
・放錯層會出咩事 —— 過期規則唔會報錯，佢會安靜咁繼續生效

**[為甚麼同一件事隔幾個月又要重新摸索？你有印象，但沒有標準 —— SOP 五個要件與第三次法則](write-your-first-sop.md)**

你唔係唔識做，你係每次都要重新記起。做得快咗但次數冇減少，所以仲係咁攰。

・三種睇落似 SOP、其實唔係嘅嘢，逐種點修
・五個要件，**缺咗第四項就唔算 SOP，只係流水帳**
・第三次法則：太早寫鎖死做法，太遲寫你已經摸索過好多次
・第一份應該揀邊件事 —— 四個條件，最少人講嗰個係最強嘅篩選器

**[跟住做：每星期 20 分鐘，令 AI context 不會愈儲愈舊](weekly-context-review.md)**

只 review 最近用過、重複出錯或被新資料推翻的 context，用 retain／update／retire 決定下一輪信甚麼。

**[為甚麼 AI 反覆犯同一個錯，加多幾句叮囑都沒用？那句話已經不在它眼前 —— 三類錯與三個檢查](ai-repeats-the-same-mistake.md)**

唔係佢唔聽話，係嗰句話已經唔喺佢眼前。呢頁解釋成個機制，同埋點分辨邊啲錯可以卡死。

・AI 其實冇記憶：每次回答都要重讀成段對話
・工作台會滿，滿咗要壓縮，而**短句最先被丟**
・三類錯：邊一類可以卡死，邊一類卡死咗會殺掉佢嘅應變能力
・三個最容易上手嘅檢查，第三個最重要

## 想由人手變成一條流程

你逐句叫佢做嘢，但你知道應該有更好嘅做法。

**[同樣用 AI，為甚麼別人快一個檔次？他在設計流程，不是下指令 —— 六步循環與七條上線前檢查](ai-workflow-loop-design.md)**

差距唔喺你問得好唔好，喺你仲逐句叫佢做嘢，而對方已經設計咗一條會自己跑完嘅流程。

・下指令 / 執行 / 循環，三層嘅實際分別
・六步循環，**缺咗第四步佢只係一個定時器**
・同傳統自動化差喺邊：一個想齊情況，一個講清標準
・上線前必答七條問題 + 第一條循環應該揀咩

## 想將 AI 工作變成可回看的證據

你開始有 output，但唔想靠 screenshot、工具名或「感覺好似快咗」去判斷是否值得繼續。

**[跟住填：將一件重複工作寫成第一張 AI work card](write-an-ai-work-card.md)**

由工作摩擦、job 名、input、artifact、review／stop 到一個 observation，填好一張可以決定 retain／revise／stop 的 AI Builder 工作卡。

**[跟住填：為一次 AI 工作寫一張不誇大的 value proof card](write-an-ai-value-proof-card.md)**

把成果、review、未知與下一個 decision 分開記低。呢頁係私有 proof record 模板，唔係客戶 case 或公開承諾。

**[跟住填：AI 話做完時，用一張 run receipt 先收貨](write-an-ai-run-receipt.md)**

一次 run 的 scope、input、artifact、checks、unknown 和 owner decision 寫清楚，先決定收貨、退回或停止；它不是 value proof 或 publication approval。

## 想帶人由「試用」走到真 adoption

唔係再派工具清單，而係先幫人完成一件安全工作，或者找出一條工作真正卡住的位置。

**[跟住帶：45 分鐘完成第一個安全 AI 成果](lead-a-first-safe-ai-outcome.md)**

一個可 review 的 internal draft 練習：最小 input、未知標記、human review 和下一輪只改一格。

**[跟住問：用五格找出 AI adoption 真正卡位](diagnose-an-ai-adoption-bottleneck.md)**

由可行性、workflow、能力、意欲、治理，找出最早不成立的一格；每輪只做一個最小介入。

## 點解用症狀分，唔用關數分

關數係**深度**，症狀係**問題**。兩樣係唔同軸。

同一個症狀，可以撞喺唔同深度嘅人身上 —— 上面「每次都要由頭嚟過」嗰三條，深入版分別喺第三關同第四關。所以用關數去排攻略，只會令你搵唔到自己。
