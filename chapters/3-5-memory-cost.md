# 點解一人公司愈用 AI 愈攰？真正樽頸常常是每次都要重新記起怎樣做

一人公司或小團隊最常見的工作摩擦，不一定是工具速度慢，而是每次相似工作再出現時，都要重新記起上次怎樣做、在哪裡找資料、哪個版本可信、誰應該 review、哪個坑不能再踩。表面上只是多花了二十分鐘，實際上會令 output 每次不同、返工更多、交接幾乎不可能。

AI 可以加快寫作、整理和執行，但若工作方法仍只在某個人的腦裡，它只會更快產生一批需要重新解釋和修正的 output。你買到的是速度，沒有買到「下次不用由零開始」的能力。這種反覆找回脈絡、重講標準、重做相同判斷的消耗，就是記憶成本。

Jimmy 的判斷是：AI 的槓桿不只在做得快，而在於減少重新學習和重新解釋的成本。先把重複工作看得見，再決定應留下 SOP、checklist、current state 還是 Skill；不要把所有事情都當成要自動化的候選。

| 記憶成本位置 | 常見表現 | 應留下甚麼 |
|---|---|---|
| 重新記起 | 又要問上次怎樣做 | 一份現行工作標準 |
| 找回資料 | 找不到最新檔、版本混亂 | source of truth／current state |
| 重做與返工 | 同類 output 每次都不同 | acceptance／checklist |
| 交接失敗 | 換人或新 AI 又由頭問 | SOP／onboarding pack |
| 過期規則 | 沿用舊做法卻不自知 | refresh／退休規則 |

## 明明工具愈來愈快，點解工作仍然愈做愈攰？因為每次都在重新學一次

有些工作並不難，但每隔幾星期再做時就像第一次：忘了去哪裡找資料、哪個格式是現行、上次為何這樣決定。你重新找回脈絡後才能開始，然後又因為標準不清被打回。這些時間很少會出現在任何報表裡，卻會一直吃掉小團隊的注意力。

AI 若只收到一段模糊要求，也會重演同一件事。它不知道上次收貨的格式、哪條 feedback 仍有效、哪些資料已過期，所以每次都要用新的 chat 重新猜。最後你以為 AI 沒幫到，實際上是工作記憶沒有被轉成可用 context。

Jimmy 的結論是：真正昂貴的不是重新打字，而是每次同類工作都要重新找回自己的判斷。

一件重複工作的真實成本可先拆成：

| 成本 | 平時容易忽略甚麼 |
|---|---|
| 執行時間 | 實際寫、整理、檢查的時間 |
| 重新記起 | 回想步驟、標準和例外 |
| 找回資料 | 搜尋檔案、版本、舊 chat、owner |
| 重做成本 | 因不一致、漏項或誤解而返工 |

你不必先精確計算分鐘數。只要看見哪一格最常令工作停住，已經知道第一個值得留下的記憶不是甚麼。

## 哪些工作值得留下來？先找每次都要重新問、重新找、重新想的三件事

不是每件事都值得記錄。一次性工作、完全探索中的嘗試，或一年只做一次的複雜特殊案，可能重新摸索反而比維護文件更便宜。若把所有事情都寫成流程，你會得到另一種成本：一堆沒人維護、也找不到的筆記。

最值得處理的，是已經重複出現、每次都卡在相近地方、而且若少一次猜測就能明顯降低返工的小工作。這些問題通常藏在「又要問一次」「上次那份在哪」「點解今次又唔同」之類的日常抱怨裡。

Jimmy 的結論是：先處理最常重播的摩擦，不要因為想建立系統而記錄所有事情。

每周可問三條：

1. 哪三件事每次都要重新問、重新找或重新想？
2. 如果明天熟手不在，哪一件會即時停住？
3. 上次同類工作，你能否說出當時為何這樣決定？

答得出第一條的，通常是第一批值得寫下來的候選；答不出第三條的，則代表你有印象，未必已有真正標準。

## SOP、checklist、current state、Skill 有咩分別？不要用同一種文件解所有問題

「寫低」不是一種產物。有些工作需要解釋整條做法，有些只需要防止漏掉昂貴步驟，有些只需要說清 project 現在在哪，有些才真正適合包成可重跑的 AI 能力。若全部叫 SOP 或全部塞進 prompt，下一位很難知道要看哪一種。

按問題選擇留下甚麼，會令記憶變得可用而不是收藏。它也能防止常見跳級：流程仍未看清，就急著把它寫成 Skill 或 automation，結果只是把錯誤更快重複。

Jimmy 的結論是：公司記憶不是一堆文件；它是不同工作問題各自留下正確、可找到的證據與標準。

| 產物 | 它回答甚麼 | 最適合何時使用 |
|---|---|---|
| Current state | 現在做到哪裡、誰下一步？ | project 正在運行、要交接 |
| SOP | 這件重複工作應怎樣做？ | 做法開始收斂、約第三次後 |
| Checklist | 有沒有漏掉會出事的關鍵項？ | 執行／review 當下 |
| Skill | 這條穩定流程可否由 AI 重跑？ | input、output、exception、驗收已穩 |

一件工作可以同時有幾種產物，但各自責任不同。先問你缺的是現況、標準、防漏還是可重跑能力，再決定應寫哪一張。

## Checklist 點樣先唔會變成另一份冗長 SOP？只放漏咗會出事的項目

很多 checklist 失敗，是因為它把每個小動作都列進去：開哪個檔、按哪個按鈕、寫哪句話。這令執行者只會勾格，不會理解工作；更糟的是，真正昂貴的失敗點被淹沒在一長串瑣碎動作裡。

checklist 的價值在於最後一刻捕捉「一漏就會造成大返工、風險或無法收貨」的事情。它不取代 SOP 的背景與理由，而是在執行或 review 時幫你避免已知高代價錯誤。AI 也可協助對照，但人仍要決定不確定情況。

Jimmy 的結論是：checklist 不是流程濃縮版；它只保留漏掉就會出事的關鍵檢查。

一條 AI 輔助工作可先檢查：

1. 有沒有只使用已批准／可公開的材料？
2. 未知、矛盾或假設有沒有清楚標示？
3. 有沒有把敏感資料、外發或不可逆行動交給人手 approval？
4. output 是否有足夠欄位讓 reviewer 收貨？
5. 有沒有留下下次可以查回的 source、decision 或 run evidence？

若某一項漏了不會造成實際問題，就不必放進 checklist。短而常用的表，比長而無人看的表更能降低記憶成本。

## 「寫咗」點解仍然等於找不到？公司記憶需要入口、owner 和更新，不只需要文件

不少團隊其實已寫過很多 SOP、模板和決定，仍然覺得每次都由零開始。問題不一定是文件質素，而是它們散在不同地方、沒有入口、沒人知道哪份最新、規則過期後也沒有退休。寫下來但找不到，對下一位而言和沒寫一樣。

公司記憶不是一個巨大的資料庫名稱，而是一種工作安排：重要標準有可發現入口，現行版本有 owner，過期內容不會冒充今日規則，工作跑完能留下可被下次找到的判斷。這些條件令一份 SOP 能由孤立磚塊變成可用牆面。

Jimmy 的結論是：記憶只有在下一位能找到、相信並安全使用時，才真的為公司省到重新學習成本。

| 缺甚麼 | 會發生甚麼 | 最小修法 |
|---|---|---|
| 入口 | 知道存在但找不到 | 在 project／stage 首頁連到現行文件 |
| Owner | 沒人知道誰可改 | 為每份重要規則寫 refresh owner |
| 狀態 | 舊版冒充現行 | 標最近更新、source of truth |
| 回收 | 做完沒有留下方法 | 在 review 留一條 next-time rule |

不用先做大型知識庫。先讓一條今天會再用的標準能被正確找到，已經開始建立真正的工作記憶。

## 用每周公開 briefing 跑一次：怎樣由重播記憶變成下一次可用的工作資產

以下是 synthetic 例子。假設小組每周用指定公開材料做 internal briefing。以前每次都要問哪份資料最新、是否要標未知、誰最後 review；即使 AI 可以很快起稿，熟手仍要重新補一次所有背景。

第一輪不需要建 Agent。先留下 current state、minimum SOP 和五項 checklist：current state 說本周在哪，SOP 說固定骨架，checklist 防止來源／未知／review 漏掉。每次跑完，若再出現同一摩擦，才把 feedback 更新進正確位置。

| 摩擦 | 留下的產物 | 下一輪怎樣少猜 |
|---|---|---|
| 不知現在做到哪 | Current state | 一打開便知 state、owner、blocker |
| 每次重講流程 | Minimum SOP | AI／同事按同一 input、output 起稿 |
| 常漏來源或未知 | Checklist | review 前可對照關鍵項 |
| 規則開始穩定 | Skill 候選 | 先做 bounded test，再決定是否封裝 |

Jimmy 的結論是：AI 的價值不只是把 briefing 寫快，而是讓每次 run 留下一條下一次不用再從頭找回的工作判斷。

這個例子不代表所有工作都值得變成 Skill。若一件事每次條件完全不同，保留一張 current state 或 decision note 已可能比維護複雜流程更合適。

## 今日怎樣減少第一筆記憶成本？先把一個重複摩擦寫成 current state

最好的第一步不是整理所有歷史筆記，也不是買另一個 AI tool。選一件剛剛做完、下星期可能又要做、而且你很清楚剛才在哪裡重新找過資料或重新解釋過的低風險工作。將它壓成目標、現在狀態、已定決策、blocker、owner 和下一步。

這張 current state 不會解決所有事情，但它令下一位第一次不用重播歷史就能開始。當你累積兩三次同類 run，再判斷是否需要 SOP、checklist 或更成熟的 Skill；不要在記憶仍然模糊時急著自動化。

Jimmy 的結論是：看得見才管理得到；先留下能減少重播的一格，再談速度和自動化。

第一輪請做：

1. 選一件最近重做過的低風險工作；
2. 寫下它最常重播的資料、判斷或步驟；
3. 選 current state、SOP 或 checklist 其中一種正確產物；
4. 指定 owner、最近更新與一條 stop／refresh rule；
5. 下次先用這份記錄，而不是重新翻所有 chat。
