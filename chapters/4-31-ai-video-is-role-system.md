# AI 影片工具不停換，怎樣先建立一條不會跟工具一起失效的影片系統？

想用 AI 做影片的人，常常卡在同一個位置：今天看見一個模型可以生成畫面，明天另一個可以自動剪片，於是收藏了一長串工具。但真正要交一條片時，仍然要自己找素材、補腳本、確認品牌字句、改錯字幕、等 render，再逐格看有沒有不應對外的內容。

問題不在於工具不夠強，而在於很多流程把「工具按鈕」誤當成「影片工作」。換了模型、訂閱到期、或影片由廣告改成教學時，原本的工具鏈就斷掉，因為沒有人說清楚每一格要交甚麼、由誰驗收、錯了要回去哪裏改。

Jimmy 的判斷是：AI 影片不應先被設計成固定工具鏈，而應先被設計成一條有角色、有輸入、有 review 的工作系統。工具可以按需要換，留下來的是訊息、腳本、素材、剪輯狀態、品質閘和 release owner；這些才令 AI 影片真的可以重跑和交接。

| 影片系統的一格 | 它解的工作問題 | 完成後留下甚麼 |
| --- | --- | --- |
| 訊息與受眾 | 片做得靚，但不知道要令誰明白甚麼 | 一句受眾問題與可驗收訊息 |
| Script／storyboard | 生了很多畫面，仍組不成故事 | 可 review 的節奏、鏡頭與口白骨架 |
| 素材與權利 | 找到畫面卻不清楚能否使用 | 已批准素材清單與來源狀態 |
| Edit state／render | 改動散在多個版本，無法重現 | 可讀的剪輯狀態、輸出版本與設定 |
| Review／release | 不知誰該擋住錯字、事實、品牌或版權問題 | 有 owner 的品質閘與發佈決定 |

## AI 影片工具很強，為甚麼仍然做不出一條可交付影片？

一個 AI 影片工具可以替你生成 B-roll、把文章變成初稿、做配音或自動裁切長片。這些都是很有用的局部能力；但一條可交付影片還要把訊息、素材、節奏、品牌、事實和發佈渠道接起來。任何一格沒有完成線，最後都會由人臨時補洞。

例如一個 synthetic 的教學短片任務，AI 很快生出十個「未來辦公室」畫面，卻未必知道影片是給第一次接觸 AI 的香港 SME 員工、還是已經懂 prompt 的團隊主管。受眾不同，畫面、術語、例子和 CTA 都不同；沒有這個 context，畫面再華麗也不等於解到工作問題。

**Jimmy 的結論：** AI 影片的完成線不是「成功 render」，而是指定受眾看過後，能理解一個被驗證過的訊息；而團隊知道每個選擇由誰做、可否重改、在哪一關收貨。

把一次影片先看成幾份要交付的東西：

| 交付物 | 不是甚麼 | 最少要能回答甚麼 |
| --- | --- | --- |
| 訊息卡 | 一句籠統題目 | 誰在甚麼情況需要明白甚麼？ |
| Storyboard | 一堆生成 prompt | 每 5–10 秒在推進哪個觀點？ |
| 素材包 | 電腦內所有圖片 | 這些素材是否已批准、是否適合這條片？ |
| Edit state | 一個最終 mp4 | 下一個人能否找到版本、改動點與輸出設定？ |
| Review receipt | 「我覺得可以出」 | 誰確認過事實、品牌、版權及 release？ |

當這些交付物存在，AI 可以幫你加快其中任何一格。若只得一個「幫我做影片」prompt，AI 只能猜其餘所有格，亦無法替你承擔猜錯的成本。

## AI 影片 production 的角色怎樣拆，才不會每一步都靠同一個人救火？

把影片流程拆角色，不代表一定要聘請很多人或開一隊 Agent。對一個人或小團隊而言，角色只是把不同類型的判斷分開：有些是內容判斷、有些是技術執行、有些是對外責任。你可以同一個人兼任多個角色，但不能讓它們在同一段模糊指令裡消失。

特別是用 AI 時，最容易混在一起的是「生成」與「批准」。AI 可以協助把 brief 變成 storyboard、把素材排成初剪，卻不應同時決定一個未核實說法能否出街、或一個畫面是否符合品牌和權利要求。把角色拆開，問題才會有地方被擋住。

**Jimmy 的結論：** 角色不是組織圖，而是一張責任地圖：哪一格負責產出、哪一格負責判斷、哪一格有權停止 release，都要看得見。

最小影片 role card 可以是這樣：

1. **訊息 owner**：確認受眾、核心主張、不能錯的事實與 CTA。
2. **Script／storyboard owner**：把訊息拆成可 review 的開場、節奏、畫面與口白。
3. **素材／edit operator**：整理已批准素材、運行 AI 工具、保存可讀 edit state。
4. **品質 reviewer**：核對字幕、事實、品牌、權利、敏感內容和渠道要求。
5. **Release owner**：只在 review 完成後決定是否發佈，並留低版本與回饋。

一開始可以由同一人戴不同帽子完成，但 review 時要真正停一停，當成另一個責任來看。這比開五個沒有清楚權限的 AI Agent 更可靠。

## AI 生成影片素材前，要怎樣判斷哪些素材、事實和權利可以用？

AI 生成不代表素材可以隨意使用。無論是公司既有相片、客戶畫面、第三方 logo、音樂、數據截圖，還是 AI 生成的示意畫面，都可能帶有使用範圍、人物私隱、商標、版權或事實表述的問題。工具可以合成畫面，但它不知道你的品牌承諾和對外責任。

最危險的做法，是把所有本機資料夾、private vault、客戶資料或對話紀錄一次過餵給影片 Agent，期望它「自己揀」。一旦 context 混了，Agent 可能把未公開的資料、不可引用的截圖或不適用的主張帶進影片，後面就很難靠剪輯修正。

**Jimmy 的結論：** 素材管理不是創作前的行政工夫，而是 AI 影片可以安全重用的邊界；只讓工具接觸本次已批准、已標明用途的素材包。

做第一條片前，先為素材留一張簡單清單：

| 素材類型 | 可以怎樣處理 | 不能假設甚麼 |
| --- | --- | --- |
| 自己已公開的文章／圖片 | 可作內容依據或視覺方向，仍需核對版本 | 不代表所有延伸主張都已被證明 |
| 已授權的品牌資產 | 按品牌規格使用，保留來源位置 | 不代表可交給任何第三方工具長期保存 |
| AI 生成示意畫面 | 標明是示意、檢查錯字與不合理細節 | 不代表它可證明真實案例或成效 |
| 客戶、CRM、內部會議素材 | 預設不放進公開 production 流程 | 不代表有檔案存取權便可公開使用 |

如果素材身份未清楚，最好的動作是先留白、換成 generic synthetic 視覺，或交回 owner 確認。不要用「影片很趕」作為跳過素材邊界的理由。

## AI storyboard 怎樣由一句主張變成可 review 的畫面和節奏？

很多 AI 影片初稿看起來很忙：有很多轉場、很多漂浮介面、很多旁白，但觀眾看完不知道重點。通常不是生成模型的問題，而是 storyboard 沒有把「一條主張」拆成有因果的節奏；每一個鏡頭只是在展示工具，而不是推進讀者的理解。

Storyboard 的作用是把抽象判斷變成可被挑錯的結構。當你在生成前已看見開場的痛點、錯誤做法、轉念、工作示例和安全下一步，reviewer 可以在成本最低的時候改方向，而不必等 render 完才說整條片不對。

**Jimmy 的結論：** 好的 AI storyboard 不是為 AI 寫更多 prompt，而是讓人能在生成前確認「觀眾為何要繼續看、每段在證明甚麼、哪裡不應誇大」。

例如一條 45 秒的 synthetic 教學短片可先用這個骨架：

1. **0–5 秒：工作痛點** — 「AI 出片很快，為何你還是每次由零開始？」
2. **5–12 秒：錯誤理解** — 用工具清單／炫技畫面，不能替代影片工作流程。
3. **12–28 秒：核心轉念** — 將影片拆成訊息、素材、edit state、review 四格。
4. **28–38 秒：小型工作例子** — 先做一條有素材清單和 human review 的短片試跑。
5. **38–45 秒：安全下一步** — 先填 role card，暫時不要把私有素材接進 Agent。

這種骨架可以換工具、換渠道、換片長，但核心判斷保持一致。等到人已批准 storyboard，才讓 AI 產生畫面、配音或剪輯變體，返工成本會小很多。

## AI 剪輯和 render 做完後，怎樣留低可交接的 edit state？

一個 mp4 只告訴你某次輸出長甚麼樣，卻未必告訴你為何選這段畫面、字幕從哪個版本來、改過甚麼、下次怎樣重做。當 AI 參與生成和剪輯，這個問題更明顯：工具設定、素材選擇和人工修正很容易散在不同聊天、下載資料夾和時間線裡。

可讀 edit state 的目的不是記錄每一下滑鼠點擊，而是保存足夠資訊，讓下一個人或未來的你能安全接手。這可以是一個專案資料夾加一份簡單 changelog，不必是一套昂貴 DAM 或複雜資料庫。

**Jimmy 的結論：** 影片真正可重用的資產，不只是一條成片；還包括令它可以被理解、被修改、被重跑的 edit state。

每次輸出前後，最少留低：

| 要留甚麼 | 為甚麼要留 |
| --- | --- |
| 已批准 storyboard／script 版本 | 知道這條片原本要說甚麼 |
| 素材清單與已用版本 | 知道畫面、音效、字幕從哪裡來 |
| AI 生成／剪輯的可重跑設定 | 下次不用靠記憶重猜 |
| 人手修改與原因 | 分清是品質改善還是方向改變 |
| Render 名稱、日期、渠道規格 | 知道哪一個才是可 review 的輸出 |

不需要把私人 prompt、客戶資料或任何敏感素材放入公開指南或共享資料夾。保留的是工作狀態與決定的摘要，足夠讓流程延續，又不會擴大不必要的存取範圍。

## AI 影片的品質 review 怎樣同時處理事實、品牌、品味和 release？

影片 review 不是看一次「靚唔靚」就完。字幕可能漏字、AI 生成畫面可能有不合理細節、旁白可能把條件講成保證、品牌語氣可能忽然變得浮誇。這些風險的性質不同，若只由同一個人憑感覺一次過掃過，容易在趕時間時漏掉重要問題。

把 review 分層後，AI 也可以協助，例如找字幕時間碼不一致、核對指定品牌字句是否出現、列出素材清單。但 Agent 的檢查結果仍然是 review input，不是發佈批准；尤其涉及事實、客戶、成效或法規時，必須由有責任的人確認。

**Jimmy 的結論：** 品質閘不是降低創作速度，而是把「哪些東西不能靠生成模型自己決定」放回清楚的 human approval 點。

一個 practical 的 review 順序：

1. **訊息**：這條片有沒有答中預定受眾問題？有沒有把意見說成事實？
2. **事實與邊界**：數字、案例、產品說法和示範是否可支持、可公開？
3. **品牌與品味**：語氣、logo、配色、節奏是否符合指定渠道和品牌？
4. **技術**：字幕、聲音、比例、連結、最後畫面是否可用？
5. **Release**：誰確認可以出、會出到哪個渠道、保留哪一個版本？

只要其中一格未通過，影片就應返回相應角色修改，而不是硬著頭皮 release。這是可回退 workflow 的一部分，不是「AI 做得不夠好」的證明。

## 想用 AI 做第一條影片，最安全的試跑怎樣設計？

第一條試跑不應該是一次大型 campaign，也不應該把 Agent 直接接到素材庫或社交帳戶。選一個低風險、已有公開資料、能被人逐格 review 的小題目，例如把一段已公開的教學觀點轉成 30–45 秒 synthetic 示意短片；這樣你可以看清 AI 最適合幫哪一格，以及哪一格仍需要人。

這次試跑的目標不是證明 AI 可以完全取代創作團隊，而是驗證一條小 workflow 是否有清楚輸入、可 review 的中間物和可信的輸出。即使最後決定不發，所留下的 role card、storyboard、素材清單和 review receipt 仍然是下次可以改善的資產。

**Jimmy 的結論：** 第一條 AI 影片的成功，是跑出一個安全、可回看的 production loop；不是把影片自動發出去，或收集最多新工具。

可以由這五步開始：

1. 只選一個已公開、可證實的主張和一個受眾問題。
2. 填一張 role card，指定訊息、素材、review 和 release owner。
3. 只提供已批准的素材包，先讓 AI 交 storyboard 和一個粗略版本。
4. 依次做訊息、事實、品牌和技術 review，記下修改原因。
5. 保留 edit state 和 review receipt，才決定是否做渠道版本或擴大流程。

暫時不要將客戶素材、未公開策略、私訊、CRM 資料或自動發佈權限交給影片 Agent；也不要因為一條 demo 順利，就聲稱已建立 autonomous video system。想把創作 workflow 留下可檢查 state，讀：[創作工作仍需要 grammar](3-16-creative-work-needs-grammar.md)。想看 Agent 如何交出可驗收 artifact，讀：[答案不等於一份工作](4-22-answer-is-not-work.md)。
