# AI 第二稿點先真係好過第一稿？Review 不是最後一眼，是下一次的學習 loop

你叫 AI「再改靚啲」很多次，但每次修改都像抽卡：這次好像順了，下次又重犯同一種錯。你可能已花很多時間 review，卻沒有一套方式分清究竟是材料不足、結構不對、語氣不合，還是任務本身沒有講清。

AI 寫得順不代表已經可用。它可能沒有根據材料、讀者不明、結構不支持決定，或把未知寫得太肯定；而 review 若只留下一句「專業一點」或「不是我想要」，人和 AI 都學不到下一次應怎樣做得更好。

Jimmy 的判斷是：review 不是最後一眼，而是一條學習 loop。先在 draft 前定 rubric，review 後再留 revision memo，下一次 context 才會真正少一個重複錯。

| Review 在哪裡發生 | 你要看甚麼 | 留下甚麼 |
|---|---|---|
| Draft 前 | 何謂可收貨 | 三至五條 rubric |
| First draft 後 | 哪些條件過／不過 | pass、revise 或 stop 決定 |
| Revision 後 | 改動是否真的解決問題 | 三行 revision memo |
| 下一次前 | 哪個 lesson 重複成立 | 少量有範圍的 context rule |

## AI 第二稿為何未必更好？沒有 rubric 的重寫只是在抽卡

叫 AI「再改好一點」聽起來很合理，但它沒有說明「好」是甚麼。AI 可能令文句更流暢，卻仍然漏了來源、答錯讀者問題、把未知寫成肯定，或把一個不適合本輪的建議寫得更完整；你只會感到第二稿「有些不同」，未必知道是否更可用。

當 review 沒有明確標準，人很容易用當下感覺判斷，並在每次對話重新發明一次要求。這令同一份工作難以交接，也令下一次 AI 不知道應優先修甚麼；重寫愈多，不代表學習愈多。

**Jimmy 的結論：** 第二稿是否更好，不看它改了多少字，而看它是否通過本輪已寫明的可驗收條件。

| 只叫「再好一點」 | 用 rubric review |
|---|---|
| AI 自行猜何謂好 | 人先定本輪三至五個條件 |
| Output 不同，但未必更可用 | 能指出哪一條已過、哪一條未過 |
| 修改只留在這次 chat | 可留下 revision memo 給下次 |
| 很難知道何時應停止 | 有 pass／revise／stop 三種決定 |

先把收貨條件寫出來，AI 的重寫才會由「換另一個答案」變成「針對一個可看見的缺口修正」。

## AI draft 前要定哪些 rubric，才不會只靠「感覺啱唔啱」收貨？

Rubric 不需要很長。對一件低風險任務，三至五條就足夠：例如是否根據批准材料、是否適合讀者、結構是否支援下一個決定、unknown 有沒有露出、是否能交給下一位 reviewer。每一條都要讓人看得到、判斷得到。

不要把 rubric 寫成「要有質素」「要專業」這類難驗證詞。若你不能說明怎樣看出它過或不過，AI 也無法用它自查；把抽象偏好翻成欄位、證據、讀者行動或明確邊界，review 才有共同語言。

**Jimmy 的結論：** Rubric 的工作不是限制創意，而是讓人和 AI 同時知道這份 draft 怎樣才算可以進入下一步。

| 模糊要求 | 可 review rubric | 怎樣檢查 |
|---|---|---|
| 「不要亂講」 | 每個重要主張可回到本輪 evidence；未知要標示 | 有沒有來源／待確認欄？ |
| 「寫給新手」 | 每段先說真工作摩擦，再解釋術語 | 開頭有沒有從讀者問題開始？ |
| 「要清楚」 | 讀者能知道要做甚麼、為何、下一步是甚麼 | 能否用三句重述？ |
| 「方便 review」 | 固定用指定欄位／結構交回 | Reviewer 能否逐格看？ |
| 「不要越界」 | 不外發、不更新系統、不補未批准資料 | Output 有沒有超出 scope？ |

Rubric 要跟這次工作走。下一篇技術文件、對外內容和內部 briefing 的收貨條件不同；不要把一份清單硬套所有任務。

## AI 第一稿交回後，pass、revise、stop 分別代表甚麼？

很多人只會在「採用」和「唔用」之間選。其實 review 至少有三個結果：pass 是通過本輪條件、可以交下一位 owner 看；revise 是有清楚條件未過、要針對修正；stop 則是資料、權限、專業判斷或任務本身未準備好，不應再靠多一次 prompt 硬撐。

這個分法很重要，因為 pass 不等於可直接對外，revise 不等於 AI 很差，stop 也不等於失敗。它們只是說明下一個正確動作不同；一旦你能分開，review 便不再變成漫長的逐句改稿。

**Jimmy 的結論：** Review 的成果是清楚決定下一步，而不是一段模糊的好／不好感覺。

| 決定 | 代表甚麼 | 下一步 |
|---|---|---|
| **Pass** | 本輪 rubric 已過，可進入指定 owner review | 保留 artifact 與未知；不等於自動外發 |
| **Revise** | 有一兩條明確條件未過 | 指出 criterion，針對修正後再 review |
| **Stop** | Evidence、權限、範圍或 owner 不足 | 補資料、縮小任務、找 owner 或暫停 |

```text
Review 決定：pass／revise／stop
已通過的 rubric：＿＿＿＿＿＿＿＿＿＿
未通過的 rubric：＿＿＿＿＿＿＿＿＿＿
下一步只做：＿＿＿＿＿＿＿＿＿＿
不可做：＿＿＿＿＿＿＿＿＿＿
```

若你無法說明為何 revise 或 stop，通常表示 rubric 還太模糊。先修 review 標準，不要連續叫 AI 再生多一版。

## AI revision request 點樣寫，先令它真正針對未過條件修改？

「再短一點」「專業一點」這類指示可能有用，但它們只描述表面。較好的 revision request 要指出哪一個 rubric 未過、現在看到的問題、可用材料或邊界有沒有改，以及它應只修哪一段、不可順便擴大範圍。

這種寫法不代表你要把 AI 當作機械人逐句控制。相反，你把人真正關心的條件說清，AI 才有空間在合適範圍內提出更好做法；而 reviewer 下次也能看到第二稿為何與第一稿不同。

**Jimmy 的結論：** 好 revision request 不是叫 AI 猜你的不滿，而是把未過 rubric 轉成一個有範圍的修正任務。

| 只說 | 改成這樣說 |
|---|---|
| 「寫得專業一點」 | 「Rubric 2 未過：讀者是初學者。先用一件真工作講問題，再保留術語解釋。」 |
| 「不要亂講」 | 「Rubric 1 未過：沒有 evidence 的成效主張改成待確認或刪除。」 |
| 「表格不好看」 | 「Rubric 4 未過：改為來源、重點、unknown、下一步四欄。」 |
| 「再改一次」 | 「只修第一、三段；不新增外部事實，不改後面已通過部分。」 |

```text
請只修正以下未過 rubric：＿＿＿＿＿＿＿＿＿＿
目前問題：＿＿＿＿＿＿＿＿＿＿
可用 evidence／範例：＿＿＿＿＿＿＿＿＿＿
不可改動或不可新增：＿＿＿＿＿＿＿＿＿＿
交回時請說明每一條 rubric 怎樣被處理；未知仍要保留。
```

修訂後再以同一份 rubric 看一次。若問題是材料不足或任務錯了，不要叫它修文法；應該回到 pass／revise／stop 的正確分流。

## AI 第二稿 review 後要留甚麼 revision memo，才會令下一次真的不同？

Revision memo 不是全文 changelog，也不是要記下每一個逗號。它只記三件事：改了甚麼、對應哪條 rubric、這個 lesson 下次是否可能有用。三行足夠讓下一次工作回看一個可解釋的修正，而不是重新閱讀整段對話。

重點是不要太早把每條 memo 都升成永久 rule。一次修改可能只是本輪讀者、日期或格式要求；只有相近任務裡反覆出現、原因穩定的 lesson，才值得交到 feedback rule 的流程。

**Jimmy 的結論：** Revision memo 是本輪 review 的收據；它令第二稿為何較好可被看見，也讓長期規則只從重複 evidence 長出來。

```text
改了甚麼：＿＿＿＿＿＿＿＿＿＿
對應哪條 rubric：＿＿＿＿＿＿＿＿＿＿
下次是否值得沿用：是／否／再觀察，因為＿＿＿＿＿＿＿＿＿＿
```

| Memo 例子 | 應否升成 rule | 原因 |
|---|---|---|
| 本輪日期未確認，改為待確認 | 再觀察／可能適用 | 需看是否經常有未確認資料 |
| 新手文章先用真工作開場 | 可能升成 rule | 在同類讀者多次被確認才夠穩 |
| 今次標題要縮短適合版面 | 不升 | 明顯是一次性 deliverable 需要 |
| 成效主張要回到 evidence | 多數值得保留 | 可能是跨多類內容的安全邊界 |

每次留下短 memo，會比保存整個 conversation 更易在下一份 draft 前被真正找到和使用。

## 用公開教學 outline 示範一次：review loop 如何決定第二稿應改甚麼？

假設要根據公開資料起一份 internal teaching outline。第一稿有五段，資料來源也列了，但第一段一開始只講工具功能，沒有說明讀者到底要完成哪一件工作；同時課程時長仍未確認。

這時不需要說「整篇重寫」。Rubric 可以指出：新手入口未過、unknown 要保留；review 決定是 revise。AI 只需修第一段，以真工作摩擦開場，並把時長留成待 owner 確認，不應自行填一個數字。

**Jimmy 的結論：** 好 review 不會令第二稿做得更多；它令第二稿只針對本輪真正未過的條件修正。

| Rubric | 第一稿狀態 | Review 決定 |
|---|---|---|
| 重要資料可回到公開材料 | 通過 | 保留 |
| 新手先看到真工作問題 | 未過 | 修第一段 |
| Unknown 必須可見 | 部分未過 | 時長標待確認 |
| Internal draft 不對外承諾 | 通過 | 保留 |
| Reviewer 可看清下一步 | 通過 | 保留 |

```text
Revision memo：
- 改了甚麼：第一段改為「已會用 AI 但交不到真工作」的工作摩擦；時長改標待確認。
- 對應 rubric：新手入口、unknown 可見。
- 下次是否沿用：新手教學稿再觀察；時長標示屬資料不足的通用安全做法。
```

這種 review 讓你知道第二稿為何較好，也為下次累積一條可被驗證的判斷。

## Review 甚麼時候應 stop，而不是不停叫 AI 生成下一稿？

有些問題不是重寫可解決：沒有足夠 evidence、未有資料權限、沒有人能決定關鍵內容、任務範圍太大，或 output 將用於高後果對外動作。這些情況下，即使 AI 再生成十版，內容也只會更完整地包裝同一個缺口。

Stop 的價值是保護你不把流暢 draft 當成可採用結果。它同時指向正確下一步：補資料、找 owner、改用公開／synthetic 材料、縮小成 internal exploration，或直接承認目前不值得做。

**Jimmy 的結論：** Stop 不是 review 失敗；它是在 review 發現「問題不在稿，而在工作條件未準備好」的正確結果。

| Stop 訊號 | 應做甚麼 | 不應做甚麼 |
|---|---|---|
| 核心主張沒有 evidence | 補資料或改成 unknown | 叫 AI 寫得更自信 |
| 文件是否可用未確認 | 找 owner／改用安全材料 | 把原檔直接交入工具 |
| 對外文案未有人批准 | 停在 internal draft | 直接發佈或承諾 |
| 範圍包含太多工作 | 拆出一段可驗收任務 | 一次過重做整條流程 |
| Reviewer 不知怎樣收貨 | 補 rubric 和 owner | 靠「看起來不錯」通過 |

學會 stop 會令你未來更快，因為你不會將時間花在一個本來需要人、資料或範圍決定的問題上。

## 每次 review 後，怎樣把下一稿變成 AI Super User 的可重用能力？

下一份相近工作開始時，只帶入本輪仍適用的 rubric、少量 reference rules 和最新 evidence；不要把所有 revision memo 都貼進去。AI 應先根據它們交 first draft，再由人用同一套條件決定 pass、revise 或 stop，形成短而可比較的 loop。

當你看到同一條 memo 在相近任務重複出現，才交給 feedback rule 流程；當工作已有穩定輸入、輸出、review 和 exception，才值得向 AI Operator 的 SOP 前進。這樣你的每一稿都不只是產出內容，也在改善下一次工作交接。

**Jimmy 的結論：** Review 最有價值的不是找出今次有幾多錯，而是令下一次一開始就少犯一種重複錯。

| 你下一個卡位 | 接著讀甚麼 | 會留下甚麼 |
|---|---|---|
| 想把重複 memo 變成規則 | [把 feedback 變成判斷](2-9-feedback-into-judgment.md) | Reference card |
| 想先把事實與未知分開 | [生成前先分 evidence 和未知](2-8-evidence-before-generation.md) | 四欄 brief |
| 不知 context 是否已可起稿 | [Context 是否 ready to draft](2-12-is-context-ready-to-draft.md) | Draft-ready decision |
| 同類工作已有穩定 loop | [AI Operator stage](../03-ai-operator.md) | SOP、state、exception |

可返回 [AI Super User stage](../02-ai-super-user.md) 看其他入口。例子只用公開／synthetic 情境，不代表任何客戶、公司或 DotAI 已取得的成果。
