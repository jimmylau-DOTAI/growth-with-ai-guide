# ChatGPT 新手教學：識得問 AI，點樣先可以將一件真工作交畀佢？

你可能已經用過 ChatGPT 寫 email、改文案、整理文章，甚至叫它幫你諗點子。但一去到一份真係要交畀同事、客戶或者老闆睇嘅工作，很多人都會突然停低：怕它寫錯、怕自己畀得唔夠資料，也怕最後花更多時間執手尾。

問題通常唔係你未識一條神奇 prompt。當「收件人是誰、哪些資料是真的、甚麼不能講錯、誰按最後一下」仍然只放喺你腦入面，AI 只能猜；文字就算流暢，亦未必等於它完成咗工作。

Jimmy 的重點係：第一次用 AI 做真工作，不是測試它有多勁，而是練習把一件工作交得清楚、收得返來。你要留下的不是一段漂亮答案，而是一個有材料、有完成線、有人 review 的小型工作交接。

| 你現在卡住的事 | 先做的 AI User 動作 | 完成後留下甚麼 |
|---|---|---|
| AI 回答看似合理，但不敢直接用 | 把成果和完成線寫出來 | 一份可以逐格 review 的 draft |
| 不知道 prompt 應該寫多長 | 先列材料、限制和停位 | 一張可再用的工作卡 |
| 一聽到 Agent、Automation、Codex 就覺得很遠 | 先跑通一件小而真實的工作 | 日後可交接、可優化的起點 |

## ChatGPT 已經識用，點解一到真工作就唔敢交畀 AI？

問 AI「幫我解釋甚麼是 AI Agent」，和交一份 briefing、email draft 或比較表給它做，是兩件不同的事。前者只需要一個可閱讀的答案；後者會影響下一個人怎樣理解、決定和行動，所以你自然會在意它有沒有漏資料、誤會語氣或把未知當成事實。

很多人一見 AI 的內容順眼便直接採用，之後才發現真正的條件從來未交代：讀者是誰、範圍去到哪裏、哪一項一定要核對、資料不夠時是否可以猜。不是 AI 特別「唔可靠」，而是你其實未把一份可收貨的工作交出去。

**Jimmy 的結論：** 新手第一個突破不是令 ChatGPT 答得更長，而是將模糊要求變成一份可 review 的交代。

| 只是問 ChatGPT | 把一件工作交給 AI 處理 |
|---|---|
| 「幫我總結這篇文。」 | 「把三段公開資料整理成一頁 briefing；每段列來源、日期、重點和待確認內容。」 |
| AI 給你一個答案 | AI 交一份有欄位、可核對的 draft |
| 覺得順眼就拿去用 | 有完成線，知道漏了甚麼、誰要改甚麼 |
| 資料不足時容易補完故事 | 預先規定：不足便標示待確認，不可當事實 |

當你能說清「我交甚麼出去、我怎樣收回來」，AI 才真正開始幫你減少一段工作，而不只是多寫一段文字。

## ChatGPT、Prompt、Context、Review 有咩分別，點解新手一定要分清？

搜尋「ChatGPT prompt 教學」時，容易以為只要學識寫指令就夠。Prompt 的確重要，但它只是今次交代工作的文字；它不會自動補上公司背景、可用材料、風險界線和你的質量要求。

你可以把 AI 想成一位剛加入的同事。你不會只說「幫我做好啲」，再期待他自動知道客戶背景、檔案格式、不可觸碰的資料和 deadline。你會交材料、講清成果、告訴他遇到甚麼要停，最後自己再看一次。

**Jimmy 的結論：** Prompt 不是咒語；它只是把目標、context 和 review 規則放進同一次工作交接的入口。

| 名詞 | 用工作語言講是甚麼 | 你現在要做的事 |
|---|---|---|
| **ChatGPT** | 幫你閱讀、整理、起草、比較或提出下一步的工具 | 把它當成 draft partner，不是最終負責人 |
| **Prompt** | 你今次對 AI 的工作交代 | 說清要交甚麼，不用刻意寫得花巧 |
| **Context** | 它今次可以根據的材料、背景與限制 | 只給剛夠用、可安全使用的資料 |
| **Review** | 人檢查是否可用、是否應採納的步驟 | 不把流暢 output 當作已完成工作 |

分清四個字後，你就知道哪裏出問題：不是每次都要重寫 prompt；有時是材料不足，有時是完成線未講，有時則是根本未安排人收貨。

## ChatGPT Prompt 點樣由一句要求，變成可收貨的工作交代？

一件工作最常見的失敗，不是 AI 不懂寫字，而是它收到的是「幫我處理一下」這種沒有邊界的要求。AI 會用最合理的方式填滿空白，但你的真正要求未必在它看到的材料裡。

與其一開始反覆試十條 prompt，不如先寫四格。這四格同時是你日後教同事、整理 SOP 或做 AI Agent 時會用到的工作語言；現在學會它，之後不用由零開始。

**Jimmy 的結論：** 好 prompt 的核心不是長，而是讓成果、材料、完成線和停位都找得到。

| 交代的一格 | 你要講清甚麼 | 少了它會發生甚麼 |
|---|---|---|
| **成果** | 最後交回甚麼文件、表格、草稿或清單？ | AI 交一堆內容，你不知道哪份才算完成 |
| **材料** | 今次只可根據哪些文字、欄位、文件或公開資料？ | 它容易混入猜測、舊知識或未批准內容 |
| **完成線** | 需要哪些欄位、格式或檢查點才算完成？ | 你只能憑感覺說「好像不錯」 |
| **停位** | 資料不足、矛盾、敏感或超出範圍時怎樣做？ | 它可能把不肯定的事寫得很肯定 |

最後再加一格「收貨方式」：你會核對甚麼、誰會批准、第一輪是否只可交 draft。這些界線不是阻礙 AI，而是讓你可以安心試、看見錯處、再改下一輪。

## ChatGPT 新手第一件工作揀乜？先揀可重做、可驗收的工作

第一次不應該拿最急、最重要或最敏感的工作試 AI；但也不用只叫它寫詩或想 caption。最好的是中間那一類：它有真用途，但即使做錯，你仍然看得見錯在哪裏、可以停低並重新做一次。

如果一項任務太大，例如「幫我處理所有活動 follow-up」，不要硬交給 AI。把它縮成「將三段公開活動資料整理成 internal briefing draft」，你便會看清輸入、輸出和 review 應該在哪裏發生。

**Jimmy 的結論：** 第一件 AI 工作的標準不是最容易，而是低風險、你做過、成果可見，而且可以重做。

| 篩選條件 | 你可以問自己的問題 | 合格例子 |
|---|---|---|
| 你做過 | 我知道甚麼叫做得好和漏了甚麼嗎？ | 將公開資料整理成會前 briefing |
| 材料安全 | 這些資料可否安全放進今次練習？ | 公開文章、自己寫的 synthetic 情境 |
| 成果可見 | 我能否看見一張表、一頁 draft 或一份清單？ | FAQ 草稿、比較表、meeting checklist |
| 可停止重做 | 錯了會否對外發送、覆蓋正本或改正式資料？ | 第一輪只出 draft，不外發、不覆蓋 |

若其中一格未過，不代表你未夠班用 AI，只代表要把工作再縮小。先完成一件可控制的小任務，遠比把一條大流程半交出去更有用。

## ChatGPT 實戰示範：點樣做一份可 review 的 briefing draft？

以下是公開／synthetic 練習：找三段公開文章、活動頁或公告文字，目標不是「研究市場」，而是做一份你真的可以逐格核對的 internal briefing。不要用客戶資料、會議記錄、CRM、合約、登入資料、credentials 或未公開文件來練習。

這個例子刻意保留「待確認」。新手最容易誤會 AI 的價值在於填滿空格；在真工作裡，能夠指出空格在哪裏，很多時比自信地補錯答案更有價值。

**Jimmy 的結論：** 一份好 draft 應該讓你快速看到已知、未知和下一個需要人判斷的位置。

| 你先決定的內容 | 今次的設定 |
|---|---|
| 成果 | 一頁 internal briefing draft |
| 材料 | 只限對話內貼出的三段公開資料 |
| 完成線 | 每段列來源、日期、三個重點和待確認內容 |
| 停位 | 來源不清、資料不足或互相矛盾時，不可猜 |
| 收貨方式 | 人逐格檢查來源、日期、重點和未知 |

把材料貼好後，可以這樣交代：

```text
請把以下三段公開資料整理成一頁 internal briefing draft。

成果：每段資料要有來源、日期、三個重點和待確認內容。
材料：只可以根據我在這個對話貼出的內容；不可自行補充外部事實。
完成線：用清楚標題和表格，讓我可以逐格 review。
停位：資料不足、互相矛盾或來源不清時，列為「待確認」，不可猜。
收貨方式：我會逐格檢查來源、日期、重點和待確認內容。
```

收到結果後，逐格檢查欄位是否齊、是否超出材料、它是否仍只是新 draft。過不到的地方，帶回四格修正；這不是 AI 或你失敗，而是下一輪工作交接變得更準確的證據。

## ChatGPT 幫手做工作，有咩實際好處，唔係只係快啲寫字？

「先交清楚，再收貨」聽起來比直接打一條 prompt 慢，但它省掉的是後面猜錯、改錯和來回溝通的時間。你不再只得到一段似是而非的文字，而是得到一件可以被別人接手、被自己重做的工作輸出。

這亦是從個人使用走向團隊使用的分水嶺。當你只靠自己腦內記住要求，AI 的好結果很難重現；當你留下材料、完成線和停位，下一次你、同事或另一個工具都更容易接上。

**Jimmy 的結論：** AI 最有用的地方不是取代你的判斷，而是把整理、起草、比較等可交接部分，變成更快、更清楚和更可重用的工作。

| 看得到的改變 | 為甚麼重要 | 你可以留下甚麼 |
|---|---|---|
| 少一點重做 | 開始時已有完成線，不用在答案海裏重拼 | 一個已驗證的 prompt／工作卡 |
| 較易交接 | 別人知道材料、要求和停位 | 一份可給同事 review 的 template |
| 知道它幫到哪步 | 不再只說「ChatGPT 好方便」 | 對整理、起草、比較或核對的具體判斷 |
| 為下一級打底 | 日後的 Skill、Agent、Automation 同樣需要邊界 | 一段被看清的可重複工作 |

如果你最後只留下對話紀錄，下一次仍要重新猜；如果你留下工作卡，你才開始累積自己的 AI 使用方法。

## AI Agent、Automation、Codex 同 ChatGPT 有咩分別，現在要不要急住學？

一般 ChatGPT 對話，是你每次交代一次、拿回一次回應。AI Agent 更接近在清楚範圍內接走一段有輸入、有步驟、有輸出和 review 的工作；Automation 會把固定觸發和資料流接起來；Codex 等工具則可在程式、檔案或工作區裡處理更具體的任務。

它們的名字聽起來更進階，但地基沒有改變：工作目標是否清楚？材料是否適合？輸出如何驗收？遇到例外誰停、誰決定？如果這些答案未有，即使用了更快的工具，也只會更快地放大混亂。

**Jimmy 的結論：** 不用等學完所有工具才開始；但要先跑通一件人能 review 的小工作，才值得把它升級成 Agent、Automation 或 Codex 任務。

| 工具／做法 | 最像甚麼 | 你應該在甚麼時候考慮它 |
|---|---|---|
| ChatGPT 對話 | 一次性的 draft partner | 第一次釐清工作與驗收方式 |
| Template／Skill | 可重用的做法卡 | 同一類工作已經做過幾次、條件相近 |
| Automation | 固定資料或觸發的接駁 | 輸入、輸出與例外已相當穩定 |
| AI Agent／Codex | 在受限範圍內跑多步工作的助手 | 你已知道權限、停位、review 和責任在哪裏 |

先慢後快並不是保守，而是避免把尚未理解的工作直接自動化。你現在做到「AI 交 draft、人收貨」，已經是建立 AI 能力最可靠的第一步。

## 新手用 ChatGPT 做工作，哪些資料和決定暫時唔好交出去？

不少人擔心「用 AI 是否安全」，但更實用的問法是：這次任務是否仍由人控制？第一輪是否只用安全材料？結果是否仍可停、可改、可撤回？這些問題比一個籠統的「可以／不可以」更能保護真正工作。

尤其在剛開始時，不要因為想追上 AI Agent 熱潮，就把客戶、合約、CRM 或未公開內容放進練習。能夠先做清楚低風險工作，不是落後；它是在建立你日後判斷哪些事可交、哪些事不可交的能力。

**Jimmy 的結論：** 第一輪要守住的是人手批准、資料界線和可逆性；沒有這三樣，流暢 output 也不應被當作可直接採用的結果。

| 情況 | 現階段怎樣做 | 原因 |
|---|---|---|
| 直接回覆客戶、公開發佈、付款或簽約 | 只讓 AI 起 draft，由人做最後決定 | 這些動作難以撤回，責任仍在人 |
| 客戶資料、合約、會議記錄、CRM、登入資料 | 不用作新手練習材料 | 先守住資料和授權邊界 |
| 資料不足 | 標示待確認，不要求 AI 填滿 | 不讓猜測變成假事實 |
| 想立刻串起很多工具或寫 code | 先指出想改善哪一段工作 | 工具不能代替工作設計與驗收 |

這些停位會令你更快知道何時可以放心繼續，也會讓日後合作的人看見哪一步必須由人承擔。

## 做完第一次 ChatGPT 工作後，點樣留低一張下次可再用的工作卡？

不要只留下那次 chat。對話會被淹沒，下一次你可能記不起為何當時這樣寫、哪些資料不能碰、結果怎樣才算可用。把最少的工作條件寫在一張卡裡，才會慢慢變成你自己的 prompt 資產。

這張卡不需要放在特別複雜的系統；備忘錄、文件或 project note 都可以。重要的是下次同類工作出現時，你不再從一條空白 prompt 開始，而是能夠修改已經驗證過的交代。

**Jimmy 的結論：** 你真正累積的不是 ChatGPT 對話數量，而是那些能被你和別人安全重用的工作交接。

```text
這次我要交的工作：＿＿＿＿＿＿＿＿＿＿

AI 只可以用的材料：＿＿＿＿＿＿＿＿＿＿

完成後我會看到：＿＿＿＿＿＿＿＿＿＿

遇到甚麼要停、不可猜：＿＿＿＿＿＿＿＿＿＿

我會怎樣 review 和收貨：＿＿＿＿＿＿＿＿＿＿

下次同類工作，我要補清楚的是：＿＿＿＿＿＿＿＿＿＿
```

> **耐用判斷：** AI 最先放大的，不是你的打字速度；而是你能不能把一件工作講清楚、驗清楚，再慢慢交出去。

## 想由個人 ChatGPT 練習，走到團隊 AI 工作流程？

做完第一個練習後，很多人仍會卡在「我應該揀哪件工作？」「我的交代夠不夠清楚？」「想帶同事一起試，但不想亂碰資料」。這些不是再找一個新工具便會自動解決，而是需要把真實工作的界線、材料和人手 review 一起看清。

DotAI 由真工作、合適練習和人手 review 開始，協助個人和團隊把 AI 放進可看見、可驗收的工作裡。這不是承諾一開始便做到全自動，而是先找一條值得試、能安全停下來的 workflow，再決定是否擴大。

**Jimmy 的結論：** 由個人 ChatGPT 練習走向團隊 adoption，最可靠的下一步是挑一條真 workflow 跑 pilot，而不是先買更多帳戶或接更多工具。
