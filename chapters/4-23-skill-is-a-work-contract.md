# 你以為 Skill 是一段 prompt，其實它是一份工作合約

你可能已經儲了不少 prompt：寫文章的、整理資料的、想內容方向的。它們有時很好用，但下一次再開，還是要重新解釋背景、補例子、改格式，最後又是你自己判斷「這次算不算做到」。

問題不是 prompt 不夠長，而是你存下來的只是一句開場白，不是一份可重跑的工作方法。

Jimmy 的判斷是：Skill 不是更長的 prompt；它是把已跑過幾次的工作，連同入口、材料、artifact、quality gate、例外和 reviewer 一起寫成合約。它令下一次不必由零猜，也令 AI 知道何時不能再自己做下去。

| Skill 合約部分 | 它要解的問題 | 留下甚麼 |
|---|---|---|
| 入口與 scope | 何時該用、今次只做哪一段 | 正確起點 |
| Materials／steps | 只讀甚麼、按甚麼順序處理 | 可重跑過程 |
| Artifact／check | 交甚麼、怎樣收貨 | 可驗收成果 |
| Exception／review | 何時停、誰決定例外 | 人手控制位 |

> **Prompt 是叫 AI 回應今次；Skill 是約定 AI 下次遇到同一類工作，應怎樣做、交甚麼、何時停。**

## 為甚麼好 prompt 很難變成可用做法？

一段 prompt 可以寫得很完整，仍然只針對一次輸出。它未必說得清：哪個時候才應啟用、應讀哪些材料、哪一步應留下來給下一步看、哪些錯不能接受，以及誰負責最後收貨。

所以同一段 prompt，第一次像樣，第二次換了資料便走樣；第三次換了人，大家又各自加一句「我平時是這樣做」。真正流失的不是文字，而是那套藏在你腦袋裏的工作判斷。

一份 Skill 要保存的，是這些判斷：

```text
何時用
→ 讀甚麼
→ 先做哪一步
→ 中間留下甚麼
→ 最後交甚麼
→ 怎樣檢查
→ 遇到甚麼要停
```

這就是為甚麼 Skill 比 prompt 更像一份工作合約。它不是把 AI 變成永遠正確，而是令大家都知道它的責任範圍。

**Jimmy 的結論：** Prompt 是一次開場；Skill 是把一段重複工作連同輸入、輸出、檢查和停位寫成下一次也能被人驗收的合約。

## 一個 Skill，不是愈早寫愈好

很多人一看到成功 output，便立即想把它包成 Skill。其實這往往太早。

若你只做過一次，可能只是剛好資料容易、剛好 AI 猜中、剛好你自己在旁邊補完。這時把做法固定下來，只是把偶然成功包裝成標準流程。

更好的時機是：同一類工作做過幾次，輸入和交付開始穩定，你也看得見常見錯誤和人手要判斷的位置。那時才把它寫下來，讓下一次不必從零開始。

例如一個團隊每星期都要把幾個已批准的公開來源整理成內部 briefing。第一次先由人做，看看真正需要哪些來源、甚麼格式才有用、哪些地方必須標記待確認。做過幾輪後，才把流程存成：

```text
讀指定公開來源
→ 抽出可追溯重點
→ 依固定格式起 briefing draft
→ 標記未知與矛盾
→ editor review 後才使用
```

這不是「AI 自動研究」。它是一份知道材料、交付和人手閘在哪裏的 routine。

**Jimmy 的結論：** 一次成功只能證明今次可行；只有相近工作反覆跑過、常見錯和 human review 已可看見，才值得把它固定成 Skill。

| 看到的證據 | 現時更合適的做法 |
|---|---|
| 只成功一次、資料剛好很齊 | 保留 work card 和 receipt |
| 重複幾次、格式漸穩 | 寫 Skill candidate |
| 常見例外和驗收已知 | 加 quality gate、exception、reviewer |

## 真正有價值的，是中間留下的東西

很多 Skill 只寫「先分析、再寫、再改善」。這種流程看起來有步驟，但沒有人知道它在哪一步出錯。

好的 Skill 會讓中間工作變得可看：brief、資料摘要、第一版 draft、review note。每一格不一定要是一個大檔案，但要讓下一步和下一個人知道「目前做到哪裏、憑甚麼繼續」。

這樣做不只是方便 AI。當輸出不好時，你不會只說「它今日唔得」，而是能分辨：問題是材料不足、方向不清、格式不合、還是 review 標準未寫出來。

**Jimmy 的結論：** Skill 最值錢的不是自動產出，而是每一段中間 artifact 都讓人找到失敗位置、修正後能再跑一次。

| 中間 artifact | 它幫你看見甚麼 |
|---|---|
| Brief／approved materials | AI 是否根據正確 context |
| First draft／work output | 是否交到指定 artifact |
| Review note／receipt | 哪條 quality gate 未過、下一步是甚麼 |

> **一個可管理的 Skill，不是每次都產出同一份答案；而是每次都讓你找得到哪一步需要改善。**

## 不要把所有判斷都交出去

Skill 最容易被誤解成「將人完全移走」。其實剛好相反：它把不必每次重新想的部分固定，讓人更專心處理真正需要判斷的地方。

**Jimmy 的結論：** Skill 應固定可規則化的部分，並把權限、對外承諾、敏感資料與例外決定明確交回人；沒有 stop line 的 Skill 只是在隱藏風險。

| 可以寫成規則 | 必須保留 human review |
|---|---|
| 指定來源、欄位、格式、固定檢查 | 權限、對外承諾、敏感資料、例外、最終採用 |

事實、欄位、格式、指定來源，可以有硬規則。品牌語氣、例外情況、對外承諾、敏感決定，仍應該由 reviewer 或有權責的人處理。若一份 Skill 沒有寫清楚何時要停，它不是自動化，是把風險藏起來。

下一次你想存一段 prompt，先問自己：這只是我想得到一個答案，還是我已經有一件會重複發生、能定義交付、也知道怎樣驗收的工作？

如果是後者，才值得開始寫 Skill。

想先分辨一件工作應該用 prompt、Skill 還是 automation，讀：[選最小足夠的 working form](4-8-prompt-skill-automation-decision.md)。想把做法寫得更嚴謹，讀：[Skill 是品質閘](4-6-skill-is-quality-gate.md)。

## 第一個 AI Skill candidate 應怎樣安全試跑，而不是即刻自動化？

你現在不需要把所有好 prompt 都改名叫 Skill。先找一段已反覆出現、可驗收的工作，寫出它何時開始、只讀甚麼、交甚麼、怎樣 check、遇到甚麼 stop、誰收貨。

第一步只用公開或 synthetic 材料跑一個 internal draft；第二步由 reviewer 按既定 quality gate 檢查；第三步留下 receipt，記錄哪些已穩、哪些仍需人決定。第一輪不接 CRM、付款、外發、部署或其他不可逆 action。

**Jimmy 的結論：** Skill 的完成線不是存好一份指示；是下一次相近工作可以按同一合約跑、出錯能定位、例外知道要交誰決定。

留低一份 Skill contract：入口、材料、標準、例外和 reviewer。暫時不要把一段靚 prompt 當成完整 Skill；先用 [五個 build gate](4-12-ready-to-build.md) 判斷它是否值得存。

| 試跑步驟 | 本輪只做甚麼 | 留下甚麼 |
|---|---|---|
| 1. Internal dry run | 只根據指定公開／synthetic materials 起 draft | artifact 與 unknown |
| 2. Review | 按 quality gate 判 pass／revise／stop | reviewer decision |
| 3. Receipt | 記已做、未做、例外與下一步 | 是否值得再跑的 evidence |
