# AI Agent 反覆犯錯，不一定要換模型：先把錯分清楚

你叫 AI 做一件事，它第一次漏了欄位；你在 prompt 補一句。第二次它把資料放錯位置；你再補一句。第三次它看起來很有信心地交來一份不能用的結果，你開始懷疑是不是要換模型、加多一個 Agent，或者重寫整個系統。

很多時候，問題不是 AI 不夠聰明，而是所有錯誤都被塞回同一段 prompt 裏處理。

Jimmy 的判斷是：可靠性不是加更多模型或更多叮囑，而是把錯誤分到正確控制層：可驗證的錯交給 rule／check、需要品味的錯交給 review、涉及責任與後果的錯交給 human approval。每次跑完還要留 state 和 receipt，下一次才知道應修哪一格。

| 錯誤類型 | 第一個控制位 | 留下甚麼 |
|---|---|---|
| 欄位、格式、來源、數字 | 自動／固定 check | pass-fail 結果 |
| 讀者、語氣、取捨 | reviewer | 修改原因 |
| 權限、外發、不可逆 action | human approval／stop | owner decision |

> **能由規則擋住的錯，不要只靠 AI 記住；需要品味的錯，要有人 review；涉及責任的錯，必須停在人手 approval 前。**

## 先把錯分成三種

第一種是**明確的錯**：少了指定欄位、格式不對、沒有列來源、數字對不上、讀了不應讀的資料。這些不是「AI 要再聰明一點」的問題，而是可以在交付前檢查的規則。

第二種是**質量判斷**：內容有沒有真正回答問題、語氣是否合適、例子是否貼近讀者。這些很少有單一正確答案，但可以由另一個 reviewer、checklist 或有經驗的人看。

第三種是**責任和風險**：要不要外發、要不要覆蓋原檔、要不要改價格、要不要接觸敏感操作。就算 output 看起來正確，也不應由 AI 自己決定。

```text
明確規則        → 自動 check
模糊質量        → review
責任／風險      → human approval
```

把這三類分開，才知道每次出錯應修哪一層。

**Jimmy 的結論：** 能由規則擋住的錯不要靠 AI 記住；需要判斷的錯要有人 review；有責任後果的錯必須停在人手批准前。

## 可靠，不等於每一步都加很多測試

一聽到 check，有人便想像要砌一套很複雜的工程系統。其實第一步可以很小。

假設 AI 每週幫你做一份公開資料 summary。你可以先定三條硬規則：每個重點要連回來源、沒有資料便寫「待確認」、輸出一定要按固定欄位排列。然後再由人看一件事：它有沒有抓到真正值得討論的重點。

這已經把「AI 自己說完成」變成一個有基本可信度的交付。之後若重複發現同一種漏誤，再把那一種錯加入 check。不是先幻想一個完美可靠系統，而是讓真實出過的錯不再原封不動重複。

| 每週 summary 的最小 check | 怎樣判斷 |
|---|---|
| 每個重點有來源 | 找不到來源即標待確認 |
| 固定欄位齊 | 缺一欄即 revise，不當完成 |
| 重要說法可核對 | 不可核對即不寫成結論 |

**Jimmy 的結論：** 第一個 quality gate 只需擋住已知、高頻、可驗證的錯；不要用一套巨大測試代替尚未看清的工作。

## 要留一條回復線

即使檢查做得好，AI 仍可能出錯。可靠的流程不是保證永遠不會錯，而是出錯時你知道：它改了甚麼、哪一版仍可回去、誰需要處理例外。

這就是為甚麼一次工作最好留下一點 state：輸入是哪一批、輸出在哪裏、檢查結果是甚麼、哪裡需要人決定。沒有這些，你遇到問題只可以重新問一次；有了它們，你可以定位、修改、重跑，而不是靠運氣。

| 要留下的 state | 它讓你下次做甚麼 |
|---|---|
| input／材料版本 | 查出 AI 根據了甚麼 |
| output／artifact 位置 | 比較改動與回退 |
| check 結果 | 知道哪條 gate 未過 |
| unknown／owner 問題 | 將例外交回人決定 |

> **Prompt 可以令 AI 做一次；驗收 loop 才令它做第二十次時仍然可管理。**

**Jimmy 的結論：** 每次 run 留下 input、output、check、unknown 和 owner，才有可能定位、回退和重跑，而不是出錯後再靠新 prompt 賭一次。

## 由哪一條工作開始？

不要一開始挑最有後果的工作。先找高頻、成果可看、出錯後能停下來的一小段，例如資料分類 draft、內部 briefing、內容版本整理，或一個小功能的檢查。

問自己四句：

```text
哪些錯可以在交付前直接檢查？
哪些地方一定要由人判斷？
遇到甚麼必須停止，不可自行繼續？
下一次出錯時，我能否看回它在哪一步出問題？
```

這四句比「幫我寫一個更強的 prompt」更接近可靠性。

**Jimmy 的結論：** 第一個安全試法是選低風險、可回退的 internal draft；先用公開／synthetic 材料跑一次三層控制，再決定是否擴大。

想把完成前的基本檢查寫清楚，讀：[quality gates](./4-2-人工智能做到一次唔等於可以交付.md)。想在改動後避免舊功能退步，讀：[最小 regression pack](./4-10-人工智能工作流程每次一改就怕另一格壞.md)。

## AI Agent reliability loop 跑完後，怎樣知道應補規則、加 review，還是停止擴大？

一次 run 出錯不代表要重寫整個 Agent。先回到 receipt：它錯在指定欄位、來源／資料、品質取捨，還是碰到原本不該自己決定的權限與對外後果？只有知道錯屬於哪一層，下一次的修正才不會又只加一句模糊 prompt。

同樣地，一次 run 通過也不代表可以立刻接真資料或自動外發。先看是否已在相近、低風險情境重複跑過，reviewer 是否能快速定位問題，stop line 是否真的被遵守。可靠性是逐次累積的 evidence，不是任何模型說自己做完就成立。

**Jimmy 的結論：** 每次 loop 後只修最早失效的一層：可驗證錯加 rule／check、品質錯補 review、責任錯收緊 approval；其餘範圍先不要擴大。

| Receipt 看到的訊號 | 最合理下一步 | 不應急著做 |
|---|---|---|
| 漏固定欄位／來源 | 加最小 check | 換模型或加多 agent |
| 成果不貼讀者／目的 | 補 rubric／review reference | 把品味偽裝成硬規則 |
| 碰到權限、承諾、外發 | stop，交 owner 決定 | 讓 AI 自己繼續 |
| 連續幾次相近 run 均穩 | 再考慮 Skill／bounded loop | 直接接 production action |

做到這一步，你留下的不只是一個「較可靠 AI」印象，而是一條下一次能知道如何改善、何時應停的工作線索。
