# 內容方向不是每週選題清單：怎樣把讀者問題變成 AI 可以幫你累積的長期記憶？

很多人開始用 AI 做內容後，日曆很快就排滿：追熱門字、把舊文改寫成不同平台版本、每日再出十個 hook。過了幾星期，內容數量多了，但讀者仍然說不出你真正想幫他解哪一種工作問題；團隊自己也不知道哪幾篇已經講過、哪一個誤解還未解開。

問題不是 AI 寫得不夠快，而是每次創作都像一個新開始。受眾問過甚麼、甚麼說法有證據、甚麼角度剛剛試過、甚麼地方仍有人不明白，沒有被放在同一個可回看的位置。於是 AI 只能從空白 prompt 或網上熱門題目猜下一篇，產量愈高，重複和漂移也愈多。

Jimmy 的判斷是：內容方向不是一張待寫題目表，而是受眾問題的長期記憶。它把重複出現的工作摩擦、你已有的公開證據、已回答過的觀點和仍未解開的空格連起來；有這張地圖，內容 Agent 才能幫你整理和擴展，而不會變成一部不停填滿空白的文字機。

| 內容方向的一格 | 它解的問題 | 完成後留下甚麼 |
| --- | --- | --- |
| 讀者問題 | 不知究竟在替誰解甚麼摩擦 | 用讀者語言寫下的工作情境 |
| Evidence 與邊界 | 不知哪些說法可講、哪些仍是猜測 | 可支持觀察與待確認空格 |
| 已回答地圖 | 每次換標題重講同一句 | 現有文章、課程、示範的關連 |
| 內容決定 | 題目很多，無法選下一步 | 有 owner 選過的下一個問題與理由 |
| Feedback 回流 | 發出後沒有累積 | 下次要補、要改或要停止的規則 |

## 內容題目和內容方向有甚麼分別，為甚麼 AI 不應只收到一個題目？

題目通常很短，例如「今星期寫 AI Agent」或「做一篇 Codex 教學」。它方便開始生成，但沒有說明讀者正在甚麼工作場景、他誤會了甚麼、這次要留下甚麼判斷。AI 收到這種題目後，只能依靠常見網絡語言補足 context，最後很容易寫成任何人都可以發的工具介紹。

內容方向則把題目放回一個讀者問題。例如：「已經懂得問 ChatGPT，但每次仍要自己補完後半段工作的人，常把 Agent 當成更勁聊天；需要先分清一段答案和一份可驗收工作，再試一條有 review 的小 loop。」這不是更長的 prompt，而是讓人和 AI 都知道這次文章的責任範圍。

**Jimmy 的結論：** 題目是文章的名字；方向是你決定為何要寫、替誰解哪一格問題、哪些說法不能隨便延伸的工作 context。沒有方向，AI 只能生內容；有方向，AI 才能協助建立內容系統。

同一個工具名，因為方向不同，可以變成完全不同的內容：

| 表面題目 | 讀者真正卡住的地方 | 合理的內容方向 |
| --- | --- | --- |
| 「AI Agent 是甚麼」 | 不知自己可以交甚麼工作出去 | 先把 chat output 變成可驗收小工作 |
| 「Codex 教學」 | 擔心 AI 改壞現有檔案 | 先用 scope、sandbox、review 設計可回退試跑 |
| 「AI 影片工具」 | 收藏很多工具但每次仍趕不及交片 | 先拆訊息、素材、剪輯狀態和品質 review |
| 「AI 內容」 | 發得很多但讀者不知你代表甚麼 | 先把重複受眾問題變成內容方向記憶 |

這樣寫，工具換了也不會令內容失效，因為你一直在回答的是人真正遇到的工作摩擦。

## 讀者問題要怎樣記，才不會只變成一堆模糊 persona？

「中小企老闆」、「行銷人」或「AI 初學者」這類 persona 太闊，幫不到 AI 或內容 owner 選題。它沒有指出對方正在做甚麼、哪一步最麻煩、他用甚麼字問、也沒有說明甚麼結果才算幫到他。結果大家很容易把自己的興趣當成讀者需要。

較有用的讀者問題應連到具體工作情境。它可以來自公開留言、已批准的 Q&A、教學後常見問題或可公開的觀察，但不需要保留私人對話全文或客戶身分。重點是保留問題的形狀和 context，而不是收集愈多愈好。

**Jimmy 的結論：** 內容系統記住的不是「某一類人喜歡甚麼」，而是「某人在甚麼工作環節卡住、常用甚麼語言描述、誤會了甚麼、下一步需要甚麼」。

每個讀者問題可用五格留低：

1. **工作情境**：他當時正想完成甚麼？
2. **原句或近似說法**：他怎樣描述自己的卡位？
3. **表面問題與真正摩擦**：他問工具，還是其實不知怎樣驗收或交接？
4. **可以先幫的安全一步**：一個低風險、可驗收的動作是甚麼？
5. **暫時不要承諾甚麼**：哪些效果、資料或 autonomous action 還未適合？

當記錄包含這五格，AI 可以幫你分群相似問題、找出未回答空白，卻不會把私人細節當作可公開內容。這也讓不同 stage 的學生找到合適入口，而非被一堆抽象 persona 淹沒。

## Evidence、Jimmy 判斷和未確認假設，怎樣放在同一個內容地圖？

內容方向很容易走向兩個極端：一邊是只收集外部連結，沒有自己的判斷；另一邊是把一個感覺很強的觀察直接寫成事實。前者令內容像資訊轉貼，後者則可能在沒有足夠證據時過度承諾。兩者都會令 AI 無法分清楚該引用、該解釋還是該停下。

比較穩的方法，是讓每一個方向都同時看見「外部或公開材料支持甚麼」、「Jimmy 對工作方法的判斷是甚麼」、「哪些地方仍待驗證」。這不是把文章寫得保守，而是令教學更誠實：讀者知道哪一句是可直接實踐的工作設計，哪一句只是需要在自己環境測試的假設。

**Jimmy 的結論：** Evidence 讓內容不亂猜，Jimmy 的判斷讓內容不是照抄，未確認空格則防止 AI 或作者把可能性說成保證。

一個內容方向卡可以這樣對照：

| 一格 | 要記甚麼 | synthetic 例子 |
| --- | --- | --- |
| 可支持觀察 | 公開材料實際能說明的現象 | 多步 AI 工作需要可 review 的中間 artifact |
| Jimmy 判斷 | 你如何把觀察翻成實戰方法 | 先用 work card 定義 output，才把工作交給 Agent |
| 不可越過的邊界 | 不應聲稱的因果、成效或案例 | 不因一次 demo 就說「一定節省人手」 |
| 待驗證問題 | 下一輪可以在安全試跑中學甚麼 | 在指定資料範圍下，這個 review loop 是否減少返工？ |

這張卡讓內容 Agent 能幫你整理不同版本，而不會把外部文章、私有資料或一次偶然經驗混成公開「真理」。想先整理材料本身，可讀 [內容 Agent 的第一份工作，是整理 evidence](./4-30-content-agent-starts-with-evidence.md)。

## 已寫文章、課程、hook 怎樣連成地圖，才不會不停重覆同一句？

當內容散在 blog、社交貼文、課程講義、slide 和筆記時，重覆往往不是因為沒有新想法，而是因為不知道已經在哪裡回答過。結果有人重新寫同一篇「Prompt 是甚麼」，但沒有補足讀者真正下一步；又或把一個適合短 post 的 hook 當成一篇需要完整解釋的長文。

內容地圖不要求你把所有內容合併成一篇很長的百科。它要做的是指出：這個受眾問題已有哪個入門解釋、哪篇是深入判斷、哪份是可跟著做的 walkthrough、哪一格仍然沒有安全答案。這樣每一項資產保留自己的角色，讀者和 AI 也知道何時應連去下一層。

**Jimmy 的結論：** 內容累積不是不停增加題目，而是讓每一篇、每個 hook、每節課都清楚自己正在補哪一個問題；相似內容可以互相連接，毋須假裝每次都是新發明。

可用一個最小內容地圖管理重覆：

| 資產類型 | 最適合處理甚麼 | 不應替代甚麼 |
| --- | --- | --- |
| Hook／短 post | 叫出痛點、引出一個反直覺問題 | 完整教學、證據或長期判斷 |
| 公開攻略 | 解釋機制、做法、邊界和下一步 | 私人操作紀錄或客戶案例 |
| Walkthrough | 讓讀者試一個小而安全的動作 | 跨場景的所有策略選擇 |
| 課程段落 | 有順序地引導學生練習與提問 | 每次都由零搜尋答案 |
| Evidence bundle | 支持內容決定與更新 | 直接替作者決定公開主張 |

下一次想寫新題目前，先看它能否補一個現有空格，或把一個短 hook 連到一份真正可學的攻略；不能的話，可能是題目還未經過方向判斷。

## AI 令內容產量變高時，怎樣分辨你在建立系統還是在製造更多噪音？

AI 可以令產量突然增加，這本身不是壞事。問題在於產量容易成為唯一指標：每週幾篇、每月幾條、生成幾多版本。這些數字沒有回答讀者是否更快找到合適解釋、團隊是否更少重覆返工、下一位內容 owner 是否知道要從哪裡開始。

真正的內容系統會令不確定性逐輪減少。當同一個問題再出現，你知道已有哪份解釋、哪一段仍讓人誤會、哪些 evidence 需要更新；當一條新資料進來，你知道它應補強哪個方向，而不是又另外開一個沒有連結的資料夾。

**Jimmy 的結論：** 內容產量是 output；內容方向記憶才是資產。前者可以很快變多，後者才令每一次新內容更少猜、更多承接。

每週或每輪內容 review，可檢查這四個訊號：

1. 新內容回答的是已有讀者問題，還是只追一個新工具名？
2. 它有沒有連到既有攻略、walkthrough 或下一個學習問題？
3. 有沒有把推測、一次個案或未核實數字寫成事實？
4. 發出後得到的追問，應更新哪張問題卡、brief 或內容規則？

若內容只是多了、問題地圖卻沒有變清楚，先停止擴大量產。把一兩個重覆問題整理好，通常比再加十條 generic post 更能建立可用的內容系統。

## 想建立第一份內容方向記憶，怎樣用一個安全小試跑開始？

不需要一開始就買 dashboard、接私有 vault，或讓 Agent 讀遍所有歷史對話。第一份內容方向記憶可以只覆蓋一個主題、一個 stage 或三個最近反覆出現的公開安全問題。重點是測試這張地圖能否幫你在下一次選題時少猜一次，而不是一夜之間把所有內容整理完。

例如你可以只處理「已懂用 ChatGPT、想開始交工作給 AI」這一組讀者問題：選三條已公開材料，列出他們的工作摩擦、已有攻略、未解空格和一個值得寫的下一篇。再由 owner 看它有沒有重覆舊內容、是否真的適合該 stage。這已經是一個可驗收的內容方向 test。

**Jimmy 的結論：** 第一份內容方向記憶的成功，不是有一個很漂亮的 dashboard，而是下一次你問「應該寫甚麼」時，能用真讀者問題、已有證據和清楚空格做出一個較好的決定。

可以跟這五步開始：

1. 只選一個受眾群或一個 AI stage，不要混入所有 topic。
2. 收集三個已公開、已批准的問題或材料，抹走私人身份資料。
3. 為每條問題填工作情境、可支持觀察、Jimmy 判斷、已回答資產與待確認空格。
4. 選一個最值得補的問題，寫成由 owner 批准的 content brief。
5. 發出或教學後，將新追問回填問題卡，再決定是否需要新文章。

暫時不要把私訊、CRM、客戶 meeting、未公開策略或自動發佈權限交給內容 Agent；也不要將一張題目表稱為「內容系統」。想把方向卡變成可交接的內容流程，可接著讀 [AI 寫內容，不等於你有內容系統](../../03-AI Operator（AI工作操作者）/chapters/3-14-content-system-not-ai-writing.md)；想先讓 AI 在受控範圍處理正在發生的資料，可讀 [先讓 AI 接到正在發生的資料](../../03-AI Operator（AI工作操作者）/chapters/3-13-live-data-before-ai-content.md)。
