# AI 答案點樣變成可驗收工作？先將 prompt 變成一張 task brief

你可能已經做到第一件 AI draft：叫 AI 整理資料、起草 email、列出比較表，然後自己 review 一次。但下一次做同類工作，你又要重新貼材料、重新說明讀者是誰、重新解釋哪些說法不可用；AI 幫到手，卻沒有累積成更輕鬆的做法。

這不代表你未識用 AI，也不代表一定要立即做 Agent。問題在於那次成功仍然只住在一個 chat 裡：AI 不知道哪些材料是根據、甚麼格式可用、哪一類修正下次要避免，你自己也沒有留下可以交接的工作單位。

Jimmy 的重點係：Prompt 是一次問法；task brief 才是一段可以重跑的工作交接。當你把目標、context、evidence、驗收、邊界和 feedback 留低，AI 才由「今次答得啱」開始變成「下次不用由零猜」。

| 你現在看到的摩擦 | AI Super User 要補的一格 | 留下的成果 |
|---|---|---|
| 每次都重新講背景 | 將 context 變成指定材料包 | 可重用 context pack |
| AI 起草後仍要大改 | 把「好」寫成驗收條件 | 一張 review checklist |
| 同一錯誤反覆出現 | 將 feedback 寫成可用規則 | 一條 reference card |
| 同事接手便不知上次怎樣做 | 留下 scope、輸入、輸出與版本 | 一份 task brief |

## AI Prompt 和 task brief 有咩分別，點解答得啱仍然未算交到工作？

Prompt 可以是一句很好的問題，例如「幫我把這段文字改得專業」。它適合探索、討論和一次性的起草；但一旦工作有材料、讀者、格式、限制、批准人和重複機會，一句問法便很難承載所有條件。

Task brief 不是把 prompt 寫得更長，而是把一次工作拆成別人也看得懂的交接。它讓 AI 知道依據甚麼做，也讓你在 output 回來時不必只憑感覺說「唔係我想要的」。

**Jimmy 的結論：** Prompt 是問問題；task brief 是交工作。前者可以產生答案，後者才有機會留下可驗收、可重跑的成果。

| 只用 prompt | 用 task brief 交工作 |
|---|---|
| 「幫我寫一封專業 email」 | 指定對象、已批准事實、語氣、必含欄位、不可承諾內容與 review 方法 |
| AI 交一段文字 | AI 交一份有範圍、有根據、有格式的 draft |
| 下次要重新解釋 | 下次可沿用並只更新本輪材料 |
| 「唔啱」只是一種感覺 | 可指出是 evidence、格式、邊界還是驗收不過 |

Task brief 不會令每個 output 都自動完美，但會令每一輪出錯的位置可見。你才有資料把一次使用變成下一次較少重做的工作方法。

## AI task brief 要寫哪幾格，先讓一件真工作可交接？

一件真工作不只需要目標。若 AI 不知道可以看甚麼、誰會使用成果、哪些話不能寫、甚麼情況要停，便只能用看似合理的方法補空白；你收到後又要用腦內標準逐句改回。

AI Super User 的做法，是把這些隱藏標準攤開。不是一開始建很複雜的系統，而是讓每一格有一句能用、能 review 的答案，並把它放在任務和資料旁邊。

**Jimmy 的結論：** 一份好 task brief，至少讓任何接手者找得到：要交甚麼、根據甚麼、怎樣收貨、何時要停。

| task brief 一格 | 你要講清甚麼 | 留空會發生甚麼 |
|---|---|---|
| **目標** | 最後要交回哪一份 artifact、給誰使用 | AI 不知甚麼才算完成 |
| **context／材料** | 今次只可根據哪些文字、檔案或公開資料 | AI 用常識或未批准內容補位 |
| **evidence** | 哪些是事實、日期、來源、已批准說法 | 流暢內容被誤當成已查證 |
| **輸出格式** | 表格、briefing、草稿、欄位、長度 | 你仍需手動重組 output |
| **驗收** | 三至五個可檢查條件 | 「好唔好」只留在你腦裡 |
| **邊界／停位** | 不可做甚麼；何時標待確認或交人決定 | AI 可能將未知寫成肯定 |
| **owner／回報** | 誰 review、交回甚麼修改／未知紀錄 | output 無人收貨、無法交接 |

你不必每次寫滿長篇大論；關鍵是每格能被人或 AI 找到，並可以隨本輪工作更新。這才是「交代清楚」而不是「prompt 寫得長」。

## AI context、evidence 和背景有咩分別，點解不能只靠舊 chat？

背景可以幫 AI 理解情況，但不是所有背景都是本輪可採用的根據。一段舊 chat 可能混有假設、過時決定或未確認資訊；若你把它全部當 evidence，AI 很容易把過去的討論包裝成現在的事實。

AI Super User 會把「可用材料」和「可作事實根據」分開。Context 說明任務世界觀和限制；evidence 則讓讀者、同事或 AI 知道哪些內容真的可引用、何處仍需確認。這個分別令 output 更可核對，也較容易日後更新。

**Jimmy 的結論：** Context 幫 AI 理解工作；evidence 幫人檢查它沒有把猜測當事實。兩樣都要有，但不可混為一談。

| 材料類型 | 在 brief 裡的角色 | 一個安全例子 |
|---|---|---|
| 任務背景 | 解釋目的、讀者、限制 | 這是給內部團隊 review 的 briefing |
| Context | 今次可看的文字、欄位和格式 | 三段公開活動資料＋欄位清單 |
| Evidence | 可列為事實的來源、日期、批准說法 | 原文 URL、文件日期、已批准 FAQ |
| 假設／未知 | 暫時不可作結論的地方 | 日期未確認；以「待確認」標示 |
| 舊 chat | 參考線索，未必可直接當依據 | 先抽出仍有效的規則，再確認 |

當你把 evidence 和未知放在工作卡裡，下一次不用翻整段對話找答案；你也不會因為 AI 記得了某句舊說法，便誤以為它已經被確認。

## AI output 怎樣驗收，先不會只靠「睇落幾順」？

AI 內容流暢時，人很容易把語氣好、格式漂亮誤認為工作已完成。但真正工作通常還有更重要的條件：事實是否跟材料一致、欄位是否齊、讀者是否能採取下一步、未知有沒有被清楚保留。

驗收不是最後多一層行政程序，而是你第一次交 task brief 時就要寫進去的完成線。若你只能說「幫我寫好啲」，你會每次都逐句改；若你能指出具體條件，AI 和同事才知道怎樣把 draft 推到可用。

**Jimmy 的結論：** 不要問 AI output「好不好」；問它有沒有通過本輪工作已寫明的檢查點。

| 驗收類別 | 可以怎樣寫 | 不要只寫 |
|---|---|---|
| 事實 | 每個主張能回到本輪材料；未知要標示 | 「要準確」 |
| 完整 | 每段有來源、日期、重點、待確認 | 「不要漏東西」 |
| 格式 | 以指定表格欄位交回，方便逐格 review | 「要好睇」 |
| 適用 | 讀者看完能知道下一個問題或決定 | 「要有用」 |
| 邊界 | 不新增外部事實、不外發、不改正式資料 | 「小心一點」 |

你只需挑本輪最重要的三至五項。驗收條件太多會令工作難做，太少又會變回憑感覺收貨；目標是令你能快速判斷「可採用、要修改、還是要停」。

## AI feedback 怎樣由一句「唔啱」變成下次用得返的規則？

每一次你說「語氣太硬」「沒有寫清未知」「格式不方便我 review」，其實都包含一條有價值的工作判斷。若它只留在那次對話，下一次又要重新講；若把它寫成有範圍的規則，它便開始成為你自己的 context。

不是每次修改都值得永久保存。一次偶然偏好、特定活動的例外或未確認的想法，不應被硬寫成全局規則；只有已重複出現、能說明原因、並且可指明適用範圍的 feedback，才值得留進 reference card。

**Jimmy 的結論：** feedback 不是叫 AI 再試一次；它是把你的判斷從腦內搬到下次工作可讀的規則。

| 原本 feedback | 變成可用規則 | 適用範圍 |
|---|---|---|
| 「呢段太硬」 | 面向初學者時，先用日常工作摩擦解釋，再出術語 | 初學者教學稿，不適用所有文案 |
| 「未知不要扮肯定」 | 沒有本輪 evidence 的資料，一律標「待確認」 | briefing、比較表、研究整理 |
| 「每次我都找不到來源」 | 每段主張後保留來源欄或連結欄 | 需事實核對的 internal draft |
| 「表格太難 review」 | 固定以來源、重點、未知、下一步四欄交回 | 活動 briefing 類任務 |

把規則加上「為何」和「適用範圍」，它才不會變成讓 AI 在所有情況都硬套的命令。下一篇可用 [把 feedback 變成規則](./練習-turn-feedback-into-a-rule.md) 練一次。

## 同一件 AI 工作重做第二次，怎樣令它不再由零猜？

第一次跑通只證明你找到了一個可行的方向；第二次才是看它能否被重用。不要直接把第一次聊天全文貼回去，而是取出真正有用的部分：最新材料、task brief、驗收清單，以及第一輪留下的有範圍 feedback。

這個做法也讓你看到甚麼還不穩定。如果第二輪仍然每次大改同一件事，可能不是模型問題，而是 context 缺少、驗收太模糊、或你把一個例外誤寫成一般規則。你因此得到可修正的證據，而不是單純覺得「AI 時好時壞」。

**Jimmy 的結論：** 可重用不等於原封不動複製；它是保留穩定規則、更新本輪材料、明確記下本輪不同之處。

| 第二輪保留 | 第二輪更新 | 第二輪重新判斷 |
|---|---|---|
| 成果格式、檢查點、停止線 | 本輪公開資料、日期、對象 | 哪些舊規則仍適用 |
| 已證明有用的 feedback 規則 | 新案例、已批准說法 | 哪些未知需要 owner 確認 |
| 工作卡欄位 | 輸出檔名、review owner | 是否值得再做第三次 |

```text
本輪 task：＿＿＿＿＿＿＿＿＿＿
沿用規則：＿＿＿＿＿＿＿＿＿＿
更新材料：＿＿＿＿＿＿＿＿＿＿
本輪例外／未知：＿＿＿＿＿＿＿＿＿＿
驗收方式：＿＿＿＿＿＿＿＿＿＿
完成後要寫回的 feedback：＿＿＿＿＿＿＿＿＿＿
```

這張 second-run card 的重點是比較兩次工作，而不是假設第一次做法永遠正確。當你能清楚說出「何時沿用、何時更新、何時停」，你已開始建立穩定的 AI 使用能力。

## 哪些 AI 工作現在仍然只應該停在 draft 和人手 review？

Task brief 可以令交接更清楚，但它不會自動解除資料、授權或不可逆動作的風險。即使 AI 已多次交出好 draft，涉及客戶、合約、付款、個人資料、正式系統更新或對外發送時，仍然需要按你所在組織的 owner、規則和批准流程處理。

尤其不要因為已有一份可重用 brief，便把「AI 可起草」誤解為「AI 可以自行行動」。可重用的好處是讓人更快 review 和決定，不是把最終責任由人身上移走。

**Jimmy 的結論：** task brief 令 AI 工作更可靠，但不是自動化通行證；有後果的決定和動作，仍要保留人手控制。

| 現在可以做 | 仍要人處理 | 原因 |
|---|---|---|
| 根據批准材料起 internal draft | 最終對外文案、承諾與發送 | 需負責事實、語氣與關係 |
| 整理公開資料、列待確認問題 | 使用敏感／未批准資料 | 涉及資料與權限界線 |
| 依 checklist 檢查欄位 | 更新 CRM、付款、簽約或正式系統 | 動作不可逆，需授權和紀錄 |
| 留下 feedback 規則 | 決定組織政策或高風險判斷 | AI 不替代 owner 的責任 |

這些邊界不會減低 task brief 的價值；相反，它讓你在低風險範圍真正把方法練熟，之後才有基礎討論 workflow、Skill 或 automation。

## 寫好第一張 task brief 後，AI Super User 下一步做甚麼？

寫好 brief 後，不需要立刻做一個龐大知識庫或接很多工具。先挑同一類低風險工作做第二次，將本輪 feedback 改成有原因、有範圍的規則，再看看哪些 context 每次都會用、哪些 evidence 一直缺。

當你有兩三次可比較的結果，才值得把穩定部分整理成 context pack 或工作模板；如果工作已經反覆出現且例外清楚，才開始考慮交給 AI Operator 層的 SOP、狀態和例外處理。這樣不會因為工具熱潮而過早系統化。

**Jimmy 的結論：** AI Super User 的能力，不是有更多 prompt；而是令下一次工作有比上一次更多可用 context、更清楚 evidence 和更少重複解釋。

| 你下一個卡位 | 接著讀甚麼 | 會留下甚麼 |
|---|---|---|
| 每次都要重新選材料 | [Context 怎樣複利](./2-2-context-compounding.md) | 一個最小 context pack |
| 每次修改只留在 chat | [把 feedback 變成規則](./練習-turn-feedback-into-a-rule.md) | 一張 reference card |
| 想確認材料夠不夠起草 | [Context 是否已 ready to draft](./2-12-is-context-ready-to-draft.md) | 一次 draft-ready 判斷 |
| 同一工作已反覆跑、想交接流程 | [AI Operator stage](../../03-AI Operator（AI工作操作者）/README.md) | 一份可交接 SOP 與狀態 |

可返回 [AI Super User stage](../README.md) 看其他入口。例子只用公開／synthetic 情境，不代表任何客戶、公司或 DotAI 已取得的成果。
