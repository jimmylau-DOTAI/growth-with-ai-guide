# AI 入門點解唔係收集 Prompt？先砌一個安全、懂你工作的 AI 環境

很多人一開始找 prompt template，期待一段好句子令 AI 突然懂自己。真正拿去做工作時，才發現 AI 不知道你做甚麼、不知道交付格式、不知道哪些文件可以看，也不知道做錯時應否停止；一張 prompt 清單填不了這些空位。

這不是設定做得不夠靚，而是工作環境未建立。AI 每多讀一份文件、接一個 connector、處理一個本機工作，權限與風險就會增加；若未先寫好身份、標準、材料範圍和 review，後面的工具只會把混亂加速。

Jimmy 的判斷是：AI 入門是一個工作環境配置次序。先建立能安全完成小工作的 workspace，再逐步擴大 AI 可讀、可處理、可執行的範圍；第一輪只用公開或 synthetic 材料，保留可回退和人手批准。

| 你卡住的問題 | 先補哪一層 | 留下甚麼 |
|---|---|---|
| AI 每次都不懂我是誰、為誰寫 | 工作角色與讀者 | 最小 work profile |
| AI 每次格式不一 | 輸出與驗收標準 | 一張 output checklist |
| 有資料但不知道可否給 AI 看 | 材料範圍與停位 | 一張 material check |
| 想接工具但怕失控 | 權限、dry run、review | 一次受控測試紀錄 |

## AI 新手卡住的點解是工作環境，不是一條更長 Prompt？

Prompt 能說明今次想做甚麼，但它不能替你保存所有工作條件。若 AI 不知道你的角色、讀者、輸出格式、可用材料和何時要停，你每次都要用一條更長的 prompt 補回這些背景；工作越多，這種做法越容易亂。

真正的環境不是某個 app 的設定頁，而是 AI 每次開工前可找到的最少工作規則。它可以是幾個清楚檔案、一張 task brief 或一個指定資料夾；重點是人和 AI 都知道哪些內容有效、哪些只是舊參考、誰會收貨。

**Jimmy 的結論：** prompt 解答「今次做甚麼」；工作環境解答「你是誰、可看甚麼、怎樣做好、誰批准」。

| 常見卡點 | 不是哪一種問題 | 應補的工作設定 |
|---|---|---|
| AI 不知你寫給誰 | 不是它不夠聰明 | 讀者、用途、語氣的 work profile |
| AI 每次格式不同 | 不是少一條神 prompt | 交付範例與完成欄位 |
| AI 用錯材料或亂猜 | 不是只要餵更多資料 | 指定 context、evidence 和停止線 |
| 你不敢交更多工作 | 不是你不懂工具 | 可回退範圍、人手 review 和 owner |

先補這些地基，你才不必把所有能力硬塞進一句 prompt。下一次同類工作也會更容易起步，因為不必重講不變的部分。

## AI 工作環境先設定哪五層，才不會一開始便做得太大？

五層不是一張能力考牌表，也不是要求你五日內完成。它是一個由低風險到較高風險的順序：先寫清不變的工作條件，再用一件小工作驗證，最後才處理資料連接和可能的動作。

順序的目的不是拖慢你，而是讓每一步都留下下一步需要的 evidence。若還未做過一件可驗收真工作，便直接接 connector 或自動化，通常只會令你更難找出問題是在工具、資料、規則還是任務本身。

**Jimmy 的結論：** 先環境、後權限；先可 review 的小工作，後可能改動資料或觸發動作的工具。

| 設定層 | 先做甚麼 | 它解決的問題 |
|---|---|---|
| 1. 工作角色 | 寫角色、讀者、常見工作 | AI 不必每次猜你在做甚麼 |
| 2. 輸出標準 | 寫格式、語氣、完成線和禁忌 | AI 知道何謂可 review 的交付 |
| 3. 真工作練習 | 用公開／synthetic 材料完成一份 draft | 驗證設定是否真的有用 |
| 4. 受控資料／工具 | 只讀、最小範圍、明確 owner | 不把 access 誤當成授權 |
| 5. Dry run | 模擬流程、保留停止線和 review | 先看過整條工作再考慮擴大 |

即使你只做到第三層，已經比只收藏 prompt 更接近真工作。第四、五層只在有清楚用途、權限和可回退安排時才需要。

## AI work profile 要寫甚麼，先令它知道你怎樣工作而不暴露私人資料？

很多人聽到「身份檔」便以為要寫一份履歷或把大量私人背景交給 AI。其實第一份 work profile 只要讓 AI 知道今次工作最常出現的角色、讀者、輸出習慣和判斷傾向；它不需要包含私人資料、客戶名單、帳戶資訊或未公開策略。

最有價值的部分往往不是「我喜歡甚麼」，而是你在交付時會拒絕甚麼。例如：沒有 evidence 的主張不當事實、初學者內容先講工作摩擦、資料不足時標待確認。這些是讓 AI 在起草時少走錯方向的判斷條件。

**Jimmy 的結論：** work profile 不是自我介紹；它是一張只放工作上穩定、可安全分享的角色與判斷卡。

| work profile 一格 | 可以寫甚麼 | 不需要寫甚麼 |
|---|---|---|
| 我在做甚麼 | 常見工作、服務的讀者或部門 | 完整履歷或私人細節 |
| 我為誰做 | 讀者程度、他們要作甚麼決定 | 真實客戶名單或聯絡資料 |
| 輸出習慣 | 長度、結構、語氣、必要欄位 | 每一個歷史 project 的內容 |
| 判斷傾向 | 重視 evidence、可驗收、避免過度承諾 | 未確認公司策略或機密準則 |
| 目前重點 | 今期要練的一類工作 | 不必要的所有工作歷史 |

```text
我通常處理的工作：＿＿＿＿＿＿＿＿＿＿
主要讀者與用途：＿＿＿＿＿＿＿＿＿＿
交付格式與語氣：＿＿＿＿＿＿＿＿＿＿
我會拒絕的情況：＿＿＿＿＿＿＿＿＿＿
資料不足時的處理：＿＿＿＿＿＿＿＿＿＿
```

寫完後，拿它配一件低風險 task brief 試一次。若對方看不出你會為何拒絕一個 output，便代表判斷傾向仍要更具體，而不是再加更多個人資料。

## AI 輸出標準怎樣設定，才不會每次都逐句重改？

「寫得專業」「寫得似我」這類要求聽起來有方向，但很難驗收。AI 很可能交出一段流暢文字，你仍需逐句改，因為真正的格式、必含欄位、事實根據與不可出現說法從未被寫明。

輸出標準不需要變成一份厚手冊。對一類重複工作，先選三至五個最常令你返工的條件，例如：表格欄位、主張要有 evidence、未知要標示、語氣先講實際摩擦、不可承諾未驗證結果。

**Jimmy 的結論：** 輸出標準的目的不是控制每個字，而是讓人和 AI 都能快速判斷「這份 draft 可否交 review」。

| 模糊要求 | 可驗收標準 | 如何 review |
|---|---|---|
| 「寫得清楚」 | 每段有一個工作痛點、一個判斷、一個下一步 | 是否可指出三個位置 |
| 「不要亂講」 | 沒有本輪 evidence 的資料標待確認 | 能否回到指定材料核對 |
| 「格式好睇」 | 固定以來源、重點、未知、下一步四欄交回 | 欄位是否齊、是否方便逐格看 |
| 「似我們風格」 | 先說日常工作摩擦，再說工具或術語 | 開頭是否沒有直接堆工具名 |

把最常用標準放在 task brief 旁邊；當同一修改反覆出現，才把它升成 context rule。這讓設定跟真工作一起長，不會變成一堆過時規則。

## 真工作點樣成為 AI 環境的第一個測試，而不是一場高風險實驗？

設定本身沒有價值，直到它能幫你完成一件真的會做的工作。第一個測試不應該是最急、最敏感或最難回退的任務，而應該是一件你做過、材料可安全使用、成果可以看見的 internal draft。

例如用三段公開資料做一頁 briefing：將 work profile 裡的讀者與語氣、輸出標準裡的四個欄位、task brief 裡的材料和停止線一起帶進去。你會即刻看見設定到底有沒有幫你少重講、少改漏，還是哪一格仍然太模糊。

**Jimmy 的結論：** 真工作是設定的驗收，不是把 AI 拿去冒險；第一輪只要證明它能交一份可 review draft。

| 測試設定 | 安全做法 |
|---|---|
| 工作 | 已做過的 briefing、比較表、內容 outline 或 checklist |
| 材料 | 公開、synthetic 或已批准的非敏感版本 |
| 成果 | 新建 internal draft，不覆蓋原檔 |
| Review | 檢查欄位、evidence、未知和格式 |
| 停位 | 不足資料即標待確認；不對外發送、不改系統 |

完成後只問兩件事：哪一格設定真的減少了重講？哪一格仍要由你每次補充？答案會變成下一次 work profile、標準或 context 的更新，不是要求工具「再聰明一點」。

## Connector、雲端資料和本機檔案點樣先算安全接入？

Connector 或資料連接不是「能力多了」這麼簡單；它同時是一個授權決定。當 AI 可讀檔案、雲端內容或其他工具時，你要先問用途是甚麼、讀取範圍在哪裏、誰是 owner、它能否做任何動作，以及出錯時怎樣停止。

新手最安全的次序是由公開／synthetic 材料開始、能只讀便先只讀、範圍由一個指定資料夾或一組測試檔開始。接上工具不代表可以讓 AI 自行改檔、發送、更新正式系統或擴大到所有資料。

**Jimmy 的結論：** Connector 不是 AI 能力的勳章；它是讓 AI 接觸哪些資料和工具的授權邊界。

| 接入前問題 | 先要有的答案 | 第一輪安全做法 |
|---|---|---|
| 為何需要接？ | 指定一件工作與一份 artifact | 沒有 task brief 不接 |
| 可以讀甚麼？ | 資料夾／檔案類型／資料等級 | 只選公開或測試材料 |
| 可以做甚麼？ | 只讀、只起 draft，還是可改動 | 預設只讀／不對外動作 |
| 誰負責？ | owner、reviewer、批准人 | 人 review 後才採用 |
| 出錯怎樣停？ | 明確停止線與可回退方式 | Dry run、保留原檔、不覆蓋 |

若答不清其中任何一格，先回到 task brief 和 material check。技術接得到，不等於工作準備好接入。

## AI workspace 設定點解要定期更新，而不是一次過做完？

工作會變：讀者不同、交付標準提高、新 project 出現、舊做法被淘汰。若 work profile、範例和規則永遠不更新，AI 便會照著過時 context 工作，令你以為它「愈用愈不似你」。

更新也不等於不停加資料。更重要的是刪除不再適用、標明已過期，並把新規則與舊規則的適用範圍分開。這樣你的 context 才不會變成一個 AI 不知該信哪條的雜物房。

**Jimmy 的結論：** AI 環境是工作中的活文件；真正的維護不是加得越多，而是讓有效規則保持清楚、過時規則可以退休。

| 何時檢查 | 要問甚麼 | 可以做甚麼 |
|---|---|---|
| 換了讀者或工作類型 | 舊語氣／格式是否仍適用？ | 更新 work profile 的範圍 |
| 同一 feedback 反覆出現 | 是否已成穩定標準？ | 新增一條 reference rule |
| 規則開始互相矛盾 | 是不同情境，還是其中一條過時？ | 拆範圍或標記退休 |
| 要接新工具或資料 | 舊權限／停位是否足夠？ | 重跑 connector 的五格檢查 |

不需要每日整理。當同類工作做過幾次、改動開始重複，或要擴大資料與工具範圍時，再做一次短 review 已足夠。

## 甚麼情況下暫時不需要走到 Connector 或 Automation？

不是每個人都要行到資料接入或自動化。若你的工作沒有重複性、還未做過一次可驗收 draft、或每次需要很高專業判斷，直接接工具只會增加設定和風險，未必帶來實際價值。

同樣地，AI workspace 不一定要是一個專門 app。只要你有一份 work profile、一個安全資料夾、一張 task brief 和一次 review，已經可以練習最重要的交接能力。工具之後可以換，這些工作條件則會跟你走。

**Jimmy 的結論：** 第三層的真工作練習已是很好的起點；connector 和 automation 是有明確需要、可驗收、可回退時才加入的選項。

| 你的現況 | 最適合停在哪裏 | 原因 |
|---|---|---|
| 第一次用 AI 做工作 | work profile＋安全 draft | 先學交代與收貨 |
| 同類工作仍很少 | task brief＋手動 review | 設定成本未必收得回 |
| 例外很多、標準未穩 | 多保留 feedback 紀錄 | 不要過早鎖成 automation |
| 資料敏感或權限不清 | 公開／synthetic 練習 | 先守住資料與責任邊界 |

知道何時不升級，是讓你日後真正需要升級時更快、更安心的原因。

## 設好第一個 AI 工作環境後，下一步怎樣變成可重用能力？

先用同一類低風險工作跑兩三次。每次保留本輪材料、output 和 review 後的修改原因，然後找出哪些 work profile、格式標準和 context 每次都用得著。這些才是值得整理成可重用 pack 的部分。

當你已能清楚區分穩定規則、本輪例外和停止線，下一步才是把 context 與 feedback 累積成自己的工作方式。之後若同一流程開始重複，便可轉到 AI Operator，讓 SOP、狀態與例外管理接手，而不是一開始就硬叫它做 agent。

**Jimmy 的結論：** 第一個 AI 環境的成果不是更多設定，而是你做下一件同類工作時，少重講、少重改、少冒不必要風險。

| 你下一個卡位 | 接著讀甚麼 | 會留下甚麼 |
|---|---|---|
| 每次仍要重新講背景 | [由收藏 prompt 到 context 複利](./2-2-人工智能學習點先唔係只收藏指令.md) | 最小 context pack |
| 不肯定材料是否可給 AI 看 | [哪些資料不應隨便上傳 AI](<../../01-AI User（AI使用者）/chapters/1-5-哪些資料不應隨便上傳人工智能.md>) | material check |
| 想把一次任務交代得更穩 | [AI 答案怎樣變 task brief](./2-1-人工智能答案點樣變成可驗收工作.md) | 可重跑 task brief |
| 工作已反覆、想交接流程 | [AI Operator stage](<../../03-AI Operator（AI工作操作者）/README.md>) | SOP、狀態和例外處理 |

可返回 [AI Super User stage](../README.md) 看其他入口。例子只用公開／synthetic 情境，不代表任何客戶、公司或 DotAI 已取得的成果。
