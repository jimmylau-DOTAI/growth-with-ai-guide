# 唔好每星期換 AI 工具：每種真工作先揀一個 Tier‑1 default

你裝了很多 AI app、每樣都試過一點，卻仍然不知道哪一個真正適合自己常做的工作。每逢有新模型、新 benchmark 或新 demo，又覺得原本那個不夠好；最後每個工具都只用過一兩次，沒有一個真的練到知道它在哪裡可靠、在哪裡要停。

比較「哪個模型最強」很容易，因為答案和功能一直會變；但真正令工作變穩的，是同一個工具有沒有陪你處理過同一種真工作，讓你知道應給甚麼 context、它容易誤解甚麼、應怎樣 review，以及何時不應再硬用。

Jimmy 的判斷是：Tier‑1 不等於宇宙最強，也不是品牌忠誠。它只是以你現在的工作、可用材料、風險和驗收方式，最值得先練深的一個暫定 default。

| 你真正要判斷 | 不要只問 | 要留下甚麼 |
|---|---|---|
| 工作類型 | 「這個工具勁不勁？」 | 一件清楚、重複、可驗收的工作 |
| 可用材料 | 「它支援甚麼 connector？」 | 可讀與不可讀的範圍 |
| Review | 「輸出靚不靚？」 | 人可核對的完成線 |
| Reset | 「要不要忠於一個工具？」 | 改 context、換入口或停止的條件 |

## AI 工具愈多愈難揀，點解「最強模型」不是最有用的第一條問題？

模型比較、demo 和排行榜可以提供參考，但它們不能替你回答一件更實際的事：你手上哪一段工作需要整理、起草、比較或改檔？若工作本身未被定義，任何工具看起來都既有優點又有缺點，最後只會換 app 而不會換工作方法。

即使某個工具在某種測試表現很好，也未必適合你今次的材料、資料界線、協作方式或 review 能力。反過來，一個功能較少但能讓你清楚交 task、看見 artifact、保留未知的入口，可能更適合成為第一個 default。

**Jimmy 的結論：** 選 AI 工具的起點不是誰贏，而是「我想讓它在哪一段真工作幫手、我怎樣收貨」。

| 只按工具問 | 容易發生甚麼 | 轉成工作問題 |
|---|---|---|
| 「A 同 B 邊個最勁？」 | 答案很快過期，和你任務未必相關 | 這次要交哪一種 artifact？ |
| 「它有沒有最多功能？」 | 功能多不代表可以安全使用 | 它能否處理批准範圍內的材料？ |
| 「大家都在用甚麼？」 | 借了別人的工作情境 | 我目前哪一段最常重做？ |
| 「可以一鍵自動化嗎？」 | 忽略驗收與權限 | 人能否快速 review、出錯能否停？ |

當工作問題先清楚，工具選擇會自然變少。這比每次有新模型便重新開始，更容易令你累積自己的 context 和 review 反射。

## Tier‑1 default 是甚麼，點解不是品牌忠誠或產品推薦？

Tier‑1 default 的意思很簡單：對某一類清楚工作，暫時選一個最適合練習的工具入口。它不是宣稱這個工具最好，也不代表所有資料、所有人或所有公司都應使用它；它只是讓你在相同條件下跑多幾次，才能看見它真正的優點、限制和需要補的規則。

把「暫定」寫進去很重要。工具會更新、工作會變、資料規則會變；如果你把選擇當成身份，便會在明顯不合適時仍然硬用。Tier‑1 的真正價值是提供一個穩定比較點，而不是阻止你之後換工具。

**Jimmy 的結論：** Tier‑1 是一個工作決定：在清楚範圍內，選最容易累積 context、review 和修正證據的暫定 default。

| 不是 Tier‑1 | Tier‑1 default 是甚麼 |
|---|---|
| 「全世界最強的 AI」 | 對本輪工作暫時最容易交 task 和收貨的入口 |
| 永遠不換的工具 | 有明確 reset trigger 的工作選擇 |
| 產品／價格／功能排名 | 任務、材料、artifact、review 的配對 |
| 將所有工作塞給一個模型 | 每種工作可有不同 default |

你可以有「公開資料 briefing」的一個 default，亦可以有「本機檔案 draft」的另一個 default。重要是每一個都連到工作，而不是連到工具迷信。

## AI 工具要怎樣按工作類型揀，先不會把不同需要混在一起？

「用 AI 做工作」太大，無法幫你選工具。先把它寫成一個可驗收任務：例如公開文章轉 internal research brief、把已批准文字改成課程 outline、或在本機建立一個可 review 文件 draft。不同類型的工作需要不同材料、不同 artifact 和不同停止線。

如果你把寫作、研究、檔案整理、數據判斷和對外發送放在同一個「AI 工具」問題裡，任何一個工具都會看似不夠。先分開工作，才能決定這次要優先的是可讀資料、結構化輸出、工作區改動還是人手 review。

**Jimmy 的結論：** 每種工作先揀一個 default，不是為了製造工具表，而是防止不同風險和驗收方式被混成同一個選擇。

| 工作類型 | 要先寫清的條件 | 第一輪可用成果 |
|---|---|---|
| 公開資料 briefing | 可用來源、日期、未知標記、讀者 | 四欄 brief 或研究表 |
| 內容／教學初稿 | 讀者、evidence、結構、語氣邊界 | Internal outline 或 draft |
| 檔案／工作區整理 | 可讀檔案、可改範圍、原檔保護 | 新建清單、分類 draft、變更建議 |
| 資料比較 | 欄位、計算／判斷規則、資料界線 | 比較表與待確認項目 |
| 對外流程 | owner、批准、停止線、不可逆動作 | 先只做 internal draft，不直接發送 |

把工作寫到這個程度後，你才有條件問「哪一個入口最容易幫我交回這種成果」。未寫清前，先不要把產品功能當答案。

## AI tool-fit card 要填甚麼，先讓工具選擇可以被 review？

工具選擇常靠感覺：剛剛的 demo 漂亮、朋友說好用、或第一次 output 看起來很快。但如果你想知道它是否真適合一種工作，需要一張小卡把任務、材料、收貨和 reset 放在同一頁，下一次才可以比較相同條件下的結果。

這張卡不需要做成採購表，也不需要比較所有工具。第一輪只選一種工作、一個候選入口和一個安全任務；重點是令選擇有可檢查的理由，而不是再多一張工具清單。

**Jimmy 的結論：** tool-fit card 不是為了找完美工具，而是讓你知道這個暫定 default 需要滿足甚麼、何時應停止硬用。

```text
工作類型：＿＿＿＿＿＿＿＿＿＿
這次要交的 artifact：＿＿＿＿＿＿＿＿＿＿
Permitted input：＿＿＿＿＿＿＿＿＿＿
不可給／不可做：＿＿＿＿＿＿＿＿＿＿
Acceptance checklist：＿＿＿＿＿＿＿＿＿＿
暫定 Tier-1 default：＿＿＿＿＿＿＿＿＿＿
Reset trigger：＿＿＿＿＿＿＿＿＿＿
```

| 卡片一格 | 它保護甚麼 |
|---|---|
| 工作與 artifact | 不把所有 AI 用法混在一起 |
| Permitted input | 不因功能多而越過資料邊界 |
| Acceptance checklist | 不被花巧 output 迷惑 |
| Default | 讓同類工作有穩定練習入口 |
| Reset trigger | 避免選擇變成身份或沉沒成本 |

填完卡後，已經能看出你需要的是對話工具、工作台或乾脆先不使用 AI；這比一開始比較品牌更有價值。

## 同一件工作怎樣安全比較兩個 AI 工具，而不把私有資料拿去測？

工具比較最容易不公平：第一個拿到較多 context，第二個用不同 prompt，最後只比較哪一份寫得較漂亮。若結果要幫你選 default，應盡量固定同一個低風險任務、同一份公開／synthetic 材料、同一份完成線，讓你比較的是工作表現而不是隨機條件。

第一輪不需要量很多數字，也不需要用客戶資料證明工具很強。只要看它能否清楚列來源與未知、按欄位交 artifact、是否需要大量重改、你能否理解它的取捨，已足夠做一個暫定選擇。

**Jimmy 的結論：** 好工具比較不是比誰寫得最花巧，而是比誰在相同安全條件下較容易交一份你能 review 的成果。

| 比較設計 | 安全做法 |
|---|---|
| 任務 | 公開文章 → internal research brief |
| 材料 | 同一條公開 URL／同一組 synthetic 資料 |
| Context | 同一份 task brief 和欄位定義 |
| 成果 | 來源、重點、unknown、下一步的表格 |
| Review | 是否有超出材料、漏欄、難以追蹤的主張 |
| 範圍 | 不上傳私有資料、不對外發送、不改正式系統 |

```text
請只根據指定公開材料交一份 internal brief。
每段要列來源、重點、unknown 和下一步；材料沒有說的不可補成事實。
不要使用外部未批准資料，不要作任何對外動作。
```

跑完後，選「較容易交 review」的那個暫定 default。你不是宣布它勝出，而是決定下幾次同類工作先用哪一個來累積經驗。

## AI 工具的 reviewability 點解比 output 漂亮更重要？

一份很順、很有創意的 output 可能令人驚喜，但若你找不到它根據甚麼、看不出哪些是未知、無法快速檢查格式，下一步仍然要花很多時間重新整理。對真工作而言，能否被人驗收往往比第一次看起來多漂亮更重要。

Reviewability 也影響你能否從錯誤學習。若工具只丟出一大段答案，卻沒有清楚 artifact、欄位、變更或假設，你很難指出哪一格不合格；下次便只能再說「試另一種寫法」，無法形成 context 和 feedback loop。

**Jimmy 的結論：** Tier‑1 default 應該讓你清楚看到根據、未知、成果和下一步，而不只是第一次輸出看起來很厲害。

| 可 review 的 output | 難 review 的 output |
|---|---|
| 有來源、欄位、unknown 和結構 | 一長段沒有根據的漂亮文字 |
| 能指出哪項不過 | 只能說「感覺唔啱」 |
| 保留原檔、只交新 draft | 不清楚改了甚麼／是否越界 |
| 能留下 feedback rule | 下次仍靠重新 prompt |

選 default 時可以問自己：若交給另一位同事，他能否在幾分鐘內看出這份成果可否採用？若不能，工具就算很強，也未必是這類工作的好入口。

## Tier‑1 default 何時應 keep、調整或 reset？

選了一個 default 不代表永遠不換。若 output 偶爾不理想，先不要急著 reset；可能是 task brief、context、evidence 或完成線未寫清，應先調整這些工作條件。否則你每次換工具，都把同一個未定義問題帶過去。

但若在相同、已定義的任務上，同一種錯誤重複出現、材料根本不適合放進該入口、reviewer 無法安全驗收，或需求已變，便要回到 tool-fit card 決定換工具、縮小任務或乾脆停止。這是 default 有價值的原因：你有 evidence 而不是只靠情緒換工具。

**Jimmy 的結論：** Keep、調整和 reset 都是合理結果；重點是你能說清這個決定來自工作 evidence，而不是工具崇拜或沉沒成本。

| 看到的狀況 | 較可能的決定 | 先做甚麼 |
|---|---|---|
| 偶爾格式不合 | 調整 context／acceptance checklist | 補清交付欄位和範例 |
| 同一類錯連續出現 | 檢查工作條件，再考慮 reset | 取一兩次 review evidence 比較 |
| 資料不適合交入這工具 | Reset／改為安全入口 | 不要為測試而上傳私有資料 |
| Reviewer 無法核對 output | 調整成果格式或換入口 | 改為表格／draft／readback |
| 工作本身已變 | 更新 task card | 不把舊 default 硬套新問題 |

預先寫 reset trigger，讓你在工具不適合時能平靜地換，而不是因為已投入很多學習時間便繼續在錯情境硬用。

## 每種工作都有 Tier‑1 後，怎樣避免自己又變成工具收藏家？

有不同工作 default，不代表要為每一種可能任務都裝一個新 app。先從你最常見、最可驗收的一兩類工作開始，跑多次、留下 review evidence 和 feedback，確定它們真的有重複性，才考慮新增另一個 default。

若兩個工具都只偶爾使用、沒有穩定材料或輸出，先不要為它們建立 Tier‑1。工具庫變大不等於能力變強；能在少數工作上累積可重用 context、判斷和 artifact，才會讓下一次更快而不是更亂。

**Jimmy 的結論：** Tier‑1 的數量應該跟你已驗證的工作類型走，不是跟市場上有多少新工具走。

| 現在的狀況 | 下一步 | 暫時不要做 |
|---|---|---|
| 只有一類重複工作 | 練深一個 default | 同時比較十個 app |
| 有兩類明顯不同工作 | 各寫一張 tool-fit card | 假設同一工具必須做全部事 |
| 新工具看起來吸引 | 用同一安全任務小試 | 立刻搬資料、改正式流程 |
| 已有清楚規則與 review | 再判斷是否要擴大範圍 | 因「大家都用」便換工具 |

這樣你會由工具收藏走向工作能力：每一個保留下來的 default，都有它處理的問題、可用材料和知道何時要停止的原因。

## 選好第一個 Tier‑1 default 後，下一步怎樣累積 AI Super User 能力？

下一次同類工作就用這個 default，帶著同一種 task brief、最小 context 和 acceptance checklist 跑一次。完成 review 後，寫下它真正幫了哪一段、哪個錯誤最常見、需要補哪條 feedback rule；這些才是判斷 keep／調整／reset 的 evidence。

當一類工作已能穩定交 task、留 context、回收 feedback，你已開始準備走向 AI Operator：把重複工作整理成 SOP、狀態和例外處理。若現在仍未能穩定收貨，繼續留在 Super User 練 task brief 和 review 反而更有價值。

**Jimmy 的結論：** 最好的 Tier‑1 工具不是你最愛的 AI，而是你在一種工作上最容易累積 context、review 和修正反射的 default。

| 你下一個卡位 | 接著讀甚麼 | 會留下甚麼 |
|---|---|---|
| 任務仍未交代清楚 | [AI 答案怎樣變 task brief](./2-1-from-answers-to-real-work.md) | 可重跑 brief |
| 每次 output 都要重改 | [把 feedback 變成判斷](./2-9-feedback-into-judgment.md) | Reference rule |
| 想確認 context 是否可起稿 | [Context 是否 ready to draft](./2-12-is-context-ready-to-draft.md) | Draft-ready decision |
| 同類工作已反覆交接 | [AI Operator stage](<../../03-AI Operator（AI工作操作者）/README.md>) | SOP、state、exception |

可返回 [AI Super User stage](../README.md) 看其他入口。例子只用公開／synthetic 情境，不代表任何客戶、公司或 DotAI 已取得的成果。
