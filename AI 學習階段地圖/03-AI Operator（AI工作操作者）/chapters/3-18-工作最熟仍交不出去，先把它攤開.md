# 工作明明你最熟，點解仍然交唔出去？先把工作從腦裡攤開

你可能已經儲了 examples、寫過好 prompt，也用 AI 起過不錯的 draft。但同一件工作每星期再做，仍然要由你親自解釋；換一個同事、換一個 chat、換一個 AI，大家都問「我應該由哪裡開始？」你最熟這件事，反而最難把它交出去。

問題通常不是 SOP 未夠長，而是工作仍然只存在腦裡。甚麼事才開始、可看甚麼資料、誰可決定、做到哪裡才算交件、出了事如何停——熟手都知道，但下一位看不到。AI 於是只能把未說出的條件猜成最常見版本。

Jimmy 的判斷是：能交接的工作，不是步驟寫得最多；而是下一位知道何時開始、可用甚麼、誰決定、目前在哪裡、最後怎樣收貨。這就是 AI Operator 的起點：先把一件重複工作攤開，再決定它值得寫 SOP、交給同事，還是只讓 AI 協助其中一段。

| AI Operator 五格 | 你要答的問題 | 寫清後留下甚麼 |
|---|---|---|
| Trigger | 甚麼事真的開始？ | 可辨認開始條件 |
| Input | 今次可讀甚麼？ | 已批准材料範圍 |
| Owner | 誰準備、誰 review、誰處理例外？ | 可追責角色 |
| State | 現在做到哪一格？ | 可交接現況 |
| Output／stop | 最後交甚麼、何時必須停？ | 完成線與安全邊界 |

## 你已經識用 AI，點解仍然未交得出一件工作？因為問答不等於工作合約

AI User 和 AI Super User 已經能用工具起稿、給 context、改 feedback；但這些能力仍可以只發生在一段個人對話裡。當你要將同一類工作交給另一位人、下一個 session 或 AI，它們不足以回答「現在能否開始」「誰有權決定」「做完後誰收貨」。

AI Operator 不是一個考牌級別，也不是一定要寫 code。它是你開始把重複工作做成另一位人可以接住的單位。最小成果不是漂亮流程圖，而是一張看得到目前 state、owner 和下一步的 work map。

Jimmy 的結論是：由「我識得用 AI」走到「工作可交接」，中間差的是可看見工作條件，不是更多工具。

先用這三條自查：

1. 若你今日不在，下一位知道這件工作何時才可開始嗎？
2. 他知道哪些材料可用、哪些資料不足時不可猜嗎？
3. 他交出 output 後，知道由誰按甚麼條件收貨嗎？

有一條答不到，先不用考慮 automation；先把這條工作畫出來。

## 第一張 work map 點樣畫？先用 Trigger、Input、Owner、State、Output 五格

work map 不是要把流程畫得很複雜，而是把最常藏在熟手腦裡的條件拿出來。只寫「第一步、第二步、第三步」通常不夠，因為下一位仍不知道何時應開始、哪份資料才可信、資料衝突時應找誰。

五格讓你在寫 SOP 前就先看到工作真正卡在何處。若 input 未齊，問題不在 prompt；若 owner 不清，問題不在 AI；若 output 沒有完成線，任何生成速度都不會變成可靠交付。

Jimmy 的結論是：work map 的價值不是畫圖，而是讓你第一次能區分「工作未定義」和「AI 未做好」。

```text
Trigger → Input → Owner → State → Output
                         ↘ Exception / stop
```

| 格 | 最小寫法 |
|---|---|
| Trigger | 本周指定公開材料已齊，briefing 對象已確認 |
| Input | 指定 URL、已批准格式；未知不補寫 |
| Owner | 一人 prepare、一人 review；衝突交回 owner |
| State | `new → context-ready → draft-ready → owner-review → closed` |
| Output／stop | 一份可 review draft；來源不清即 `blocked` |

只要這五格能讓另一位人覆述下一步，你已經有一個可運行的交接起點。

## 點解要先揀低風險小工作？第一輪目標是看見摩擦，不是證明 AI 有幾勁

剛開始交接時，很多人想挑最重要、最急、最複雜的工作來試，因為它看起來最有價值。但這類工作通常材料多、例外多、外部後果大，很難判斷出錯是 work map 未清、AI 不適合，還是原本工作本身已經不穩。

低風險小工作反而更適合學習。它應該使用公開或 synthetic 材料、可以人手收回、不涉及直接外發或不可逆行動，而且會在短時間內再次出現。你可以在這類工作裡安全看見 input、owner、state 或 acceptance 哪一格最常出問題。

Jimmy 的結論是：第一輪要買到的是清楚 evidence，不是一次很大、但無法解釋的 AI 成功故事。

選第一個練習時，優先有這四個條件：

1. 最近已做過至少一次，下一次大概會再出現；
2. 資料可公開、已批准或 synthetic；
3. output 可由人手 review、退回或重做；
4. 有一位 owner 願意說甚麼算完成、何時應停止。

這類練習完成後，才能誠實判斷工作是否值得向 SOP 或 Skill 前進。

## Work map 畫完後要留下甚麼？current state、minimum SOP 和 exception 各自做不同事

畫出五格後，很多人會立刻想把一切變成大系統。其實你只需要根據工作目前狀態，留下一種最合適產物。正在跑的 project 需要 current state；做法已重複且開始穩定的工作需要 minimum SOP；最常導致錯誤的條件需要 exception 或 checklist。

把這些東西分開，會令下一位知道應看哪一頁。current state 不會承擔全部歷史，SOP 不會承擔今日進度，exception 不會被埋在一段長背景裡。這是工作記憶開始可用的時刻。

Jimmy 的結論是：交接包不是資料愈多愈好，而是每種問題都有一份下一位找得到、用得對的記錄。

| 你現在缺甚麼 | 先留下甚麼 |
|---|---|
| 不知目前做到哪、誰下一步 | Current-state note |
| 同一工作每次都要重講做法 | Minimum SOP |
| 總在同一處漏項或越界 | Checklist／exception rule |
| 新同事一入 project 就迷路 | Onboarding pack |

這些產物不必一次全有。從最常令 work map 失效的一格開始補，才不會又造出一堆找不到的文件。

## 同一條工作何時先值得寫成 SOP？第三次出現才開始看得出真正 pattern

第一次做順，可能只是資料剛好齊；第二次也許仍有熟手在旁補救。太早將它寫成固定流程，容易把偶然條件或未看見的例外寫死；太遲才寫，則每次都要重新摸索。重複次數本身不是魔法，但能提供比較材料。

第三次法則是一個實戰 heuristic：第一次記實際摩擦、第二次比較差異、第三次才固定最少規則。當 trigger、input、review 和 acceptance 已開始收斂，minimum SOP 才有資格讓下一位試跑。

Jimmy 的結論是：未看清 pattern 前，不要用流程化掩蓋不確定；先讓幾次真 run 告訴你哪些條件真的要留下。

| Run | 優先做甚麼 | 不要急著做甚麼 |
|---|---|---|
| 第一次 | 記下實際 input、steps、返工位置 | 宣布它已可交給 AI 自動跑 |
| 第二次 | 比較哪些條件重複、哪些屬例外 | 把所有細節寫成硬規則 |
| 第三次 | 寫最少 SOP、acceptance、stop line | 把未驗證部分包成 Skill |

這個節奏令你在真正有 evidence 時才固定工作方法，而不是把自己的第一個猜測變成系統。

## 用公開 briefing 跑一次：由腦內工作變成一個可 review 的第一輪

以下是 synthetic 例子。假設你每周要將指定公開材料整理成 internal briefing。以前你自己知道何時材料夠、哪個 format 可用、誰會看最後版本；新同事或 AI 卻只會收到「幫我整理一下」這句話。

先用五格寫清後，AI 只做按指定材料起 draft；owner 負責確認 input、review output、處理來源衝突。這不是自動發布，也不包括任何客戶資料、報名資料或未公開資料。

| 位置 | 本輪做法 |
|---|---|
| Trigger | 本周公開材料已選定，目標讀者已確認 |
| Input | 指定 URL、已批准格式、一份 good example |
| Owner | preparer 起稿；reviewer 收貨；衝突交回 owner |
| State | `new → context-ready → draft-ready → owner-review → closed / blocked` |
| Output／stop | 一份 internal draft；來源不清、範圍改變即停止 |

Jimmy 的結論是：AI 表現好不好只是這張 map 最後看見的一格；你首先能改善的，通常是輸入、owner 和完成線。

跑完後只問一條：最早卡住的是哪一格？下一輪只修那一格，才會知道你的交接包正在變好。

## 今日就可以完成甚麼？先寫一張六行 work map，不用買新工具

第一張 work map 不需要畫圖軟件、project management app 或自動化。選一件本周已出現、可安全收回的小工作，花十分鐘寫出開始、input、owner、state、output 和 stop line。重點不是字靚，而是另一位人能否看懂。

寫完後請一個未讀過完整聊天紀錄的人或新 AI session，覆述他現在可以做甚麼、缺甚麼要停、誰會收貨。覆述不清楚時，不要加更多 prompt；回頭補最早缺的格。

Jimmy 的結論是：你未畫出工作之前，AI 只可以猜；畫出之後，你才知道應該交接、改善，還是停止。

現在請填六行：

1. 這件工作何時開始：＿＿＿＿
2. 今次只可用的材料：＿＿＿＿
3. 誰 prepare／誰 review：＿＿＿＿
4. 目前 state：＿＿＿＿
5. 最後交甚麼：＿＿＿＿
6. 看到甚麼必須停止：＿＿＿＿
