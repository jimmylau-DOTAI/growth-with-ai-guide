# 新 AI 一入 project 就要翻晒 chat？你需要的是 current-state note

你換了 AI、同事或 session 後，總要花很久重新講 project 做到哪裡、哪些決定已經改過。很多人以為「所有資料都在 chat 裡」就是最完整；但 chat 混著已放棄的方向、一次性要求、過期 next step，重讀愈多未必愈明白現在應做甚麼。

這不是記錄不足，而是沒有把「仍然有效的工作合約」從歷史過程中抽出來。下一位協作者真正需要的是目標、現況、已定決策、blocker、owner 和可 review 的下一步，而不是一整段要自己考古的對話。

Jimmy 的判斷是：chat 記錄過程；current-state note 記錄現在。先用一個低風險 project 把現行判斷壓成一頁，才讓新 AI 或新同事在清楚界線內接手；歷史仍可保留，但不應主導眼前工作。

| Current-state 六格 | 它先回答甚麼 | 留下甚麼 |
|---|---|---|
| 最後更新 | 這頁何時仍然準確？ | 時效提示 |
| 目標 | 本輪最後要交甚麼？ | 完成線 |
| 現在狀態 | 已完成、正在做、卡住甚麼？ | 可接手位置 |
| 已定決策 | 哪些方向仍有效、為何？ | 現行判斷 |
| Blocker／unknown | 哪些事不能猜？ | 停線與問題 |
| 下一步／owner | 誰要交甚麼、誰收貨？ | 下一個 action |

## 所有資料都在 chat，點解新協作者仍然接唔到？歷史不是現行狀態

chat 的好處是保留了思考過程：有人提出過甚麼方案、為何改過方向、哪一句曾經很有用。可是它也自然留下大量已失效內容。當新協作者由頭讀起，他要自己判斷哪些是暫時腦暴、哪些已經被否決、哪些今天仍有 authority；這正是最容易出錯的地方。

current-state note 不會否定 chat 的價值。它只是把「今次工作必須相信甚麼」從歷史中抽出來，令下一位不需先變成 project 考古學家才可以開始。需要深入了解時，再由 note 連回原始材料。

Jimmy 的結論是：chat 可保留過程；但只有 current state 才應該決定下一位今天怎樣工作。

先用這個對照判斷一段資訊應放在哪裡：

| 資訊類型 | 放在 chat／歷史 | 放在 current state |
|---|---|---|
| 已放棄方案 | 保留原因作日後參考 | 不列為現行方向 |
| 已確認目標 | 可回看討論過程 | 一句寫成目前完成線 |
| 未解問題 | 保留原始脈絡 | 列為 blocker，寫 owner／下一步 |
| 背景資料 | 連回原始來源 | 只保留會改變目前決定的連結 |

這樣分類後，新協作者不必靠猜，就知道哪一份文字有資格影響今輪 output。

## 一頁 current-state note 要寫甚麼？六格令下一位知道現在可以做哪一段

summary 很容易寫得順，卻不一定能交接。它可能交代了背景、歷史和很多好想法，但漏了「現在在哪一步」「誰有權改方向」「甚麼仍然未知」。下一位讀完後仍會問：「所以我現在可以開始嗎？做到甚麼才算交件？」

六格 current state 的用意，是把這些會決定下一步的問題放在一起。它不是要變成另一個資料倉；每一格都應短到有人真的願意更新，並且可以連回更完整的 source of truth。

Jimmy 的結論是：一份 current state 的好壞，不看它是否寫得全面，而看一位未參與歷史的人能否只靠它說出現在可做甚麼。

| 格 | 最小寫法 |
|---|---|
| 最後更新 | 日期＋本頁 owner |
| 目標 | 本輪可 review 的 artifact 和範圍 |
| 現在狀態 | 目前 state，不寫抽象「進行中」 |
| 已定決策 | 仍有效的方向、約束與原因 |
| Blocker／unknown | 缺甚麼、誰能確認、不可猜甚麼 |
| 下一步／owner | 誰在何時交甚麼給誰 review |

六格不用每次都寫得很長。若某一格突然要貼整份歷史，通常代表它應該只放一個連結與一句用途，而不是把 current state 再變成 chat。

## State 點樣寫先唔會只得「進行中」？每一格都要有跨去下一步的門檻

「進行中」有時只是禮貌地說「我不知道現在在哪」。它不能告訴下一位是材料未齊、draft 已完成等 review，還是 owner 尚未決定範圍。結果不同人會同時做不同部分，或不停產出 AI draft，卻沒有一份可以被真正收貨。

較清楚的 state 不需要複雜工具。重點是每一格能回答：現在已有甚麼？要去下一格還缺甚麼？誰可以說已經跨過這條線？這使 AI 也知道自己應該起稿、標記未知，還是停止。

Jimmy 的結論是：state 不是 project 管理裝飾；它是避免下一位靠舊 chat 猜進度的最小 control。

一組低風險 state 可以是：

```text
brief-ready → context-ready → draft-ready → owner-review → closed
                         ↘ blocked（缺 input／需決定／範圍改變）
```

每次更新 current state 時，只要補一句「要跨去下一格，仍要誰做甚麼」。如果答不到，代表 blocker 還沒有被寫成可處理的問題。

## 已定決策同 blocker 點樣放埋一齊？讓 AI 不會把未知寫成答案

project 很多錯誤不是因為沒有人想過，而是因為已定決策和未解問題混在同一段文字裡。例如「今次只用公開材料」可能已被確認；「某個日期是否仍正確」卻未確認。AI 讀到兩句後，很容易把後者也當成可用事實，然後寫進看似完整的 output。

把 decisions 和 blockers 放在相鄰位置，能讓任何 worker 看到「哪些可以直接依據」「哪些要標示／回問／停止」。這比在最後加一句泛泛的『請自行核對』更有效，因為邊界已經跟著工作走。

Jimmy 的結論是：有效的 current state 不只告訴人做甚麼，也要清楚告訴人甚麼暫時不能做。

| 區塊 | 例子 | 工作影響 |
|---|---|---|
| 已定決策 | 只用公開來源；output 只作 internal draft | AI 可按此整理與起稿 |
| Blocker | 有一個來源日期未確認 | 不可把日期寫成事實 |
| Owner | reviewer 確認來源是否可用 | 確認前維持 `blocked` |
| Next decision | 確認後才決定是否外發／改稿 | AI 不可自行越過 |

這樣寫時，blocker 不再只是「有問題」；它是一條讓 project 能正確停住、並有機會被解決的工作項目。

## 更新 current state 是寫日記嗎？只在會改變下一步的三種事發生時更新

很多人一聽到要留 state，便以為每次討論都要記錄。這會令 note 很快長成另一段 chat，最後又失去入口功能。相反，如果完全不更新，過期 state 比沒有 state 更危險，因為它會讓人很有信心地跟錯方向。

一頁有效 note 只在現行工作真的改變時更新。你不是要保存所有對話，而是要讓下一位每次打開時都能相信它仍然代表 project 現在的合同。

Jimmy 的結論是：current state 不是日記；它只記會改變下一步、authority 或安全邊界的事件。

以下三種事發生才需要更新：

1. **決定改了：** 方向由 A 轉 B，寫清新決定與原因。
2. **狀態改了：** 例如 draft 已可 review，或因 input 不足變 `blocked`。
3. **Owner／下一步改了：** preparer 已交件、reviewer 接手，或 approval 需要換人。

已推翻的內容不需要刪掉歷史，但應從 current state 移走或清楚標示失效。這就是保持 note 短而可信的做法。

## 用公開學習 brief 跑一次：新 AI 只靠 current state 能否安全接手？

以下是 synthetic project 例子。假設你要完成一頁公開材料的 internal learning brief。工作只用已指定公開文章、dummy 格式和內部 review；不包括客戶資料、私人聊天或 production 設定。目的是測試一頁 note 是否足以讓新協作者開始。

讓新的 AI session 或同事只看這六格，再請他覆述自己能做甚麼、不能做甚麼、應交給誰。若覆述錯了，就不要叫他再翻全部 chat；先看哪一格沒有寫清。

| 六格 | 本輪 current state |
|---|---|
| 最後更新 | 今日；learning owner 負責 refresh |
| 目標 | 一頁公開資料的 internal learning brief |
| 狀態 | `draft-ready`，等 owner review |
| 已定決策 | 只用公開來源；未知一律標示；不作外發承諾 |
| Blocker | 一個來源日期未確認，維持 `blocked` 於該部分 |
| 下一步 | reviewer 核對來源與未知，才決定改稿或 closed |

Jimmy 的結論是：一頁 current state 的成果，不是讓新 worker 永遠不問問題，而是令他第一個問題已經正確指向真正 blocker 和 owner。

這個練習只適合低風險材料。遇到敏感資料、外部承諾或高影響決定時，仍要使用相應的權限與人手審批，而不是以一張 note 取代治理。

## 今日怎樣開始？先把一個正在做的 project 寫成六格，再叫人覆述

不要等所有項目都整理好才開始。選一個你目前正在做、範圍小、可以由人手收回的 project，先只寫目標、現在狀態和下一步；然後補已定決策、blocker 和最後更新。這已經足以暴露「我們其實沒有共識」的地方。

把 note 交給一位未讀過完整歷史的人或另一個 AI session，請他覆述：現在哪一段可做？甚麼不可猜？誰負責收貨？答得不清楚時，只補最早缺的一格，不要立即把所有 chat 複製進去。

Jimmy 的結論是：chat 是歷史；current state 是讓下一位可以安全開始工作的合同。

第一輪請完成這五步：

1. 選一個低風險、正在運行的 project slice；
2. 寫出六格的最小版本；
3. 連回真正 source of truth，不貼全部背景；
4. 請另一位 worker 覆述範圍、owner 和 stop line；
5. 只更新會改變下一步的狀態、決定或 owner。

如果你仍然每次換工具就要帶大量背景，可讀 [換 AI 工具就要由零開始？你需要帶得走的不是所有資料，是可信 context](./3-9-換工具不必從零開始，帶走可信脈絡.md)。如果想把 current state 放進一個更完整 project 入口，可讀 [新同事或新 AI 一入 project 就迷路？](./3-8-新同事或人工智能入專案，用一頁交接包開始.md)。
