# SOP 唔止係步驟：點樣將一件重複工作寫成可交接的標準

你可能重複做過同一類工作很多次：整理資料、起 briefing、檢查一份 output、交接一個內容流程。自己做時看似順手；但只要換人、隔一段時間，或想交給 AI 協助，就要重新說一次「其實我想點」。步驟也許有，但甚麼算完成、哪裡可變通、遇到例外應問誰，仍然藏在熟手腦裡。

很多 SOP 因此走向兩個極端：第一次做順便把所有細節寫死，下一次一變就失效；或一直不寫，令每次都重新摸索。真正有用的 SOP 不應是百科全書，也不是一串按鈕說明；它要讓下一位知道何時開始、可以根據甚麼、做到哪裡才算交件、甚麼情況必須停。

Jimmy 的判斷是：SOP 的本質不是流程文件，而是讓下一次工作有標準可以對照。當標準被寫成可檢查、可交接、可更新的最小工作合約，人、同事和 AI 才有機會在同一任務上減少猜測。

| SOP 的位置 | 它解開甚麼 | 留下甚麼 |
|---|---|---|
| Purpose／trigger | 為何及何時開始？ | 工作範圍 |
| Input／steps | 可用甚麼、先後怎樣做？ | 可重跑做法 |
| Acceptance | 怎樣才算可交？ | 可 review 完成線 |
| Exception／owner | 出事時誰決定、何時停？ | 安全停線 |
| Refresh | 何時重看、誰更新？ | 不會過期的標準 |

## SOP 同一串步驟有咩分別？步驟教人做，標準令下一位知道何時收貨

「開檔案、填資料、交出去」可以是一串步驟，但它沒有告訴人結果是否正確、哪份資料才可相信，或範圍改變時應怎樣處理。熟手能靠經驗補位；未做過的人只會機械地跟，然後在第一個例外前卡住。

SOP 的作用是把這些隱性判斷帶到工作表面。它不承諾每次都不出錯，而是讓錯誤可以對照標準被看見、被退回，並在下一輪被修正。這就是為何它同時幫到交接和 AI：兩者都需要看得見的完成線。

Jimmy 的結論是：SOP 不是「教人點做事」，而是替一件重複工作定義最低可收貨標準。

| 只有步驟 | 有 SOP 標準 |
|---|---|
| 「整理資料後交出」 | 「只用已批准材料，交一頁含來源、未知與 reviewer 的 briefing draft」 |
| 「跟返上次 format」 | 「使用指定目前格式；舊版本只作參考」 |
| 「有問題再問」 | 「資料矛盾、範圍改變或無 owner 時標 `blocked`」 |

下一位能用這些條件判斷自己是否可開始、可否交件，SOP 才真正將工作從某個人的記憶變成可對話標準。

## 一份 minimum SOP 要有甚麼？五格已足夠讓工作第一次可交接

很多人一聽到 SOP 就想到很長的手冊，於是延遲寫，或者把所有歷史、例外和個人習慣都塞進同一頁。結果文件看似完整，卻沒有人願意打開；真正需要接手的人仍找不到最重要的開始條件和完成線。

minimum SOP 的目標不是捕捉每個可能情況，而是令一件已開始收斂的工作可以安全跑一次。只要五格能讓下一位完成本輪、把不屬於範圍的事停下來，往後才有基礎逐步加深。

Jimmy 的結論是：第一份 SOP 寧可短而能跑，也不要厚而沒有人知道哪條是真規則。

| 五格 | 要寫清甚麼 |
|---|---|
| Purpose／trigger | 這件事解甚麼、甚麼條件齊才開始 |
| Input | 目前可用資料、未知和不可用材料 |
| Steps／owner | 真正重複的動作，以及誰 prepare |
| Acceptance | 要交甚麼、誰 review、甚麼叫合格 |
| Exception／refresh | 哪些情況停、誰決定、何時更新規則 |

若任何一格要靠「你應該明」才看得懂，就先補那一格，不要急著加更多步驟。SOP 的清楚度永遠比頁數重要。

## 點解驗收條件最常被漏掉？沒有 acceptance，AI 和人都不知道何時應停

很多 SOP 把大部分篇幅放在中間步驟，最後只寫「完成後交給某某」。這令做的人可以一直忙，卻不知道輸出是否可用。AI 尤其容易在這裡產生錯覺：它交了一段文字，就以為工作結束；人則要靠感覺說「好像不太對」再要求重做。

acceptance 不一定是量化 KPI。它可以是可見欄位、來源狀態、格式、review owner 和不能越過的邊界。重點是讓收貨的人能指出哪一格未過，而不是只丟回一句抽象 feedback。

Jimmy 的結論是：沒有驗收標準的文件不是 SOP，只是流水帳；它無法讓人或 AI 知道何時已經完成。

一份 internal briefing 的 acceptance 可寫成：

1. 只用了本輪已批准的公開材料；
2. 有三個重點和清楚來源欄；
3. 未知／矛盾已標示，沒有自行補寫；
4. 格式符合指定 template；
5. owner review 後才可進下一手，不直接對外發送。

這些條件不是要消滅專業判斷，而是把最常導致退回的原因變得可檢查。下次再出問題，你就知道是 SOP 漏了條件，還是確實有新的例外。

## SOP 遇到例外時點做先不會變成死規則？把停線和 owner 寫進去

不少人害怕 SOP 因為覺得創意、客戶情況或現實工作總有例外。這個擔心是對的；但解法不是完全不寫，而是承認哪些部分可以固定、哪些部分必須由人作決定。沒有這條界線，工作要麼僵化地照做，要麼每次都把所有規則推翻。

exception 是 SOP 的安全閥。它說清楚資料不足、材料衝突、範圍突變或權限不清時，worker 不應該自行補答案，而是要標記、停止並交回有 authority 的人。這也正是讓 AI 不會「好心做錯事」的條件。

Jimmy 的結論是：可交接不等於完全自動；一份成熟 SOP 必須同時寫清可以做甚麼，和甚麼時候不應再做。

| 例外情況 | Worker／AI 應做甚麼 | Owner 要決定甚麼 |
|---|---|---|
| input 不齊 | 標 `blocked`，列缺口 | 是否補材料或縮範圍 |
| 資料矛盾 | 不把其中一份當事實 | 哪個來源是現行標準 |
| output 超出範圍 | 停在 draft，不外發 | 是否改 brief 或另開工作 |
| 規則失效 | 指出 SOP 與現況不符 | 更新／退休該條規則 |

有了這一格，例外不再等於 SOP 失敗；它是 SOP 告訴你「這裡應回到人的判斷」的證據。

## SOP 點樣避免一年後變陷阱？Refresh 不是附註，是工作的一部分

一份沒有更新責任的 SOP，最初可能很有用，過一段時間卻會變成過時陷阱。工具、資料位置、格式、owner 和工作目標都會改；但新同事看到一份寫得很肯定的文件，往往會以為自己正在跟對。這比沒有 SOP 更危險，因為錯誤有了假權威。

你不需要定期重寫所有 SOP。只要寫清它在甚麼改變下要重看、誰負責 refresh、以及最近一次確認時間，就能讓大家知道這份標準仍否有效。這也令 SOP 不會被當成永遠正確的教條。

Jimmy 的結論是：一份可維護的 SOP 不只寫「怎樣做」，還要寫「甚麼時候不能再照舊做」。

| 變動 | 要更新甚麼 |
|---|---|
| input 或 source 改了 | current reference 與未知規則 |
| output／受眾改了 | purpose、scope 與 acceptance |
| owner／權限改了 | review、approval 與 exception route |
| 重複返工 | 加入或修正最早失效的一格 |

每次更新只需要留下日期、owner 和改了哪一條。這足夠讓下一位分清現在是跟現行標準，還是在讀歷史版本。

## 用公開 briefing 跑一次：一份 SOP 怎樣由熟手做法變成可 review 工作

以下是 synthetic 例子。假設你每周要把指定公開材料整理成 internal briefing。以前只有熟手知道要看哪些來源、哪種資訊不能猜、誰會看最後版本；新同事或 AI 一加入，就要重新問很多次。

用五格寫成 minimum SOP 後，AI 只負責按已批准 input 起第一稿；人則保留材料確認、exception 和最後 review。這不是自動發布流程，也不使用客戶資料或私人背景。

| SOP 格 | 本輪寫法 |
|---|---|
| Trigger | 本周公開材料已選定，briefing 對象已確認 |
| Input | 指定 URL、格式範例；未確認資料只可標示 |
| Steps | 整理 → 起 draft → 對照欄位 |
| Acceptance | 三重點、兩未知、來源欄，由 owner review |
| Exception／refresh | 來源矛盾即 `blocked`；每次格式改變由 owner 更新 |

Jimmy 的結論是：SOP 不會令 AI 自己變可靠；它讓人第一次可以看清 AI 交回的東西究竟哪一格合格、哪一格需要退回。

跑完一次後，把遇到的真正例外補回 exception，不要把每個個案細節變成硬規則。這樣 SOP 才會隨工作成熟，而不是變成不敢碰的文件。

## 第一份 SOP 應該揀邊件事？選第三次出現、可回退、有人願意收貨的小工作

不要以最重要、最敏感或例外最多的工作當第一份 SOP。那類工作通常還未收斂，容易令你把大量未驗證的做法寫死。更好的起點是你已做過約三次、結果可以由人手收回、又有一位 owner 願意 review 的小 routine。

寫完後，不要假設它已成立。讓一位未看過所有舊資料的人或 AI 只依 SOP 跑其中一段，再看他在哪一格開始猜。卡住的地方就是下一次應補的工作條件。

Jimmy 的結論是：一份 SOP 經歷過一次「照住跑」才開始成立；未試過的只是一份筆記。

第一輪請做五步：

1. 選一件已重複約三次的低風險工作；
2. 填五格 minimum SOP，不寫所有歷史；
3. 加一條可收貨 acceptance 和一條 stop line；
4. 指定 review／refresh owner；
5. 下一次只按 SOP 跑一段，記下最早卡住的位置。
