# 為甚麼每次開新對話都要重講背景？不是 AI 記性差，是分類問題

每開一個新對話，你可能又要說一次「我想用甚麼語氣」「這個 project 做到哪裡」「哪份資料才可用」「這條流程以前怎樣跑」。把這些句子儲成一段長開場白當然能暫時解決，但它其實證明你正用人手補一個結構缺口：同一批不同性質的 context 沒有被分到正確位置。

另一種情況更難察覺：AI 記住了不該記的東西。今次的臨時要求幾個月後仍影響 output、某個 project 的規則跑到另一個 project、過期安排被當成現行事實。它通常不會報錯，只會令你覺得「最近答得有點怪」。

Jimmy 的判斷是：AI 記憶不是愈多愈好，而是要把今次 task、長期偏好、project 硬規則和可重跑 workflow 分開。這個 walkthrough 用四層幫你先分類一件重講中的背景，讓下一次新 session 不用重播歷史，也不會亂帶規則。

| 四層 | 放甚麼 | 放錯會怎樣 |
|---|---|---|
| 今次 task | 一次性要求、眼前完成線 | 臨時要求誤變永久習慣 |
| 長期偏好 | 穩定語氣、工作習慣 | 每次都要重新講 |
| Project 硬規則 | 禁區、source、權限、完成線 | 其他 project 誤用舊規則 |
| 可重跑 workflow | SOP、checklist、成熟工作方法 | 同一流程永遠只靠 chat 重講 |

## 同一句背景講咗好多次，點解唔只是麻煩？它在告訴你 context 沒有被留下

「今次不要用太正式語氣」「這個資料夾不可刪」「報告要有來源欄」這些句子看起來都像背景，但它們會活多久、影響哪一種工作、出錯後代價有多大完全不同。全部留在對話裡，下一次就要重講；全部放進長期設定，又會令舊規則安靜地干擾新工作。

重講本身不是失敗。它是一個很有用的訊號：你正在使用一條尚未被正確保存的工作判斷。與其每次複製一大段開場白，不如先問這句話到底應該只活今次、長期成立、只屬某個 project，還是其實已是一條重複流程。

Jimmy 的結論是：當你第三次講同一句背景，先不要再加長 prompt；先判斷它到底放錯在哪一層。

先將最近重講的句子寫成這四類：

| 句子類型 | 例子 | 先放哪裡 |
|---|---|---|
| 一次限制 | 「今次先不出稿」 | 今次 task |
| 穩定偏好 | 「用香港廣東話，先講工作痛點」 | 長期偏好 |
| project 邊界 | 「這個 project 只用指定公開材料」 | Project 硬規則 |
| 工作流程 | 「每次 review 前要核對來源與未知」 | SOP／Skill 候選 |

分到類別後，你不必一次過搬所有東西。先處理最常重講、又最容易令 output 出錯的一句。

## 四層各自應該放甚麼？用生命週期決定，不要只看內容重要不重要

同一條資訊重要與否，不是決定放哪裡的唯一標準。更實用的是問它何時會失效：今天結束就沒用的，不能放成長期偏好；project 完結便失效的，不能跑去影響所有對話；一條有 trigger、steps 和 acceptance 的工作，也不應塞成一句「記得要做」。

四層是按生命週期與用途分工，不是按工具名稱死背。不同平台的功能會變，但這個工作原則不會變：短命內容短放、跨工作偏好長放、project 邊界留在 project、重複流程獨立成可重跑標準。

Jimmy 的結論是：判斷一段 context 放哪裡，最重要不是它多長，而是它應該活多久、應該影響誰。

| 層 | 適合內容 | 退休／更新時機 |
|---|---|---|
| 今次 task | 今日格式、一次性範圍、眼前 output | task closed 或範圍改變 |
| 長期偏好 | 語言、解釋方式、穩定合作原則 | 你的工作方式改變時 |
| Project 硬規則 | 指定 source、禁區、owner、權限 | project 結束或規則改變時 |
| Workflow | 重複 SOP、檢查表、固定驗收 | evidence 顯示做法已變時 |

把一段資料放進任何一層時，順手寫一條 refresh／退休條件。這能阻止長期記憶慢慢長成過期規則堆。

## 偏好同硬規則點樣分？「最好」和「必須」不能寫成同一種說話

長期偏好通常可以彈性處理：你偏好短句、少 jargon、先講結論。硬規則則是違反後可能有風險或令工作失效的東西：不可用某類資料、不可外發、需要 owner approval、未知必須標示。若把兩者混在同一段「請盡量遵守」的文字裡，AI 和協作者都不易知道哪條可調整、哪條必須停。

這不代表硬規則只要寫一次就萬無一失。它仍需要人手 review 與適當權限；但把邊界寫成明確可檢查句子，至少讓 workflow 不會把關鍵限制當成普通風格建議。

Jimmy 的結論是：偏好令 output 更像你；硬規則令工作不會越界。兩者要分開寫，才各自有效。

| 類型 | 模糊寫法 | 可工作寫法 |
|---|---|---|
| 偏好 | 「寫得自然一點」 | 「用香港廣東話，先講痛點後講步驟」 |
| 硬規則 | 「最好小心資料」 | 「只用指定公開材料；未知標示；不可對外發送」 |
| stop line | 「有問題再問」 | 「資料矛盾、範圍改變或無 owner 時標 `blocked`」 |

下次 AI 沒跟時，你便知道應調整的是語氣偏好、規則表述，還是根本需要 owner 介入；不會只剩一句「它又不聽話」。

## 有第一步第二步的東西點算？流程要獨立，唔好塞進偏好或單次 chat

一條「先做 A、再做 B、最後 C」的內容不是偏好。它有自己的 trigger、input、步驟、驗收與例外；塞進長期偏好時，它要麼太長而被忽略，要麼被誤用在不相干工作。每次把同一流程散落在 chat 裡，則等於每次重新建立一份不完整 SOP。

重複流程應先在 project 內跑穩。未成熟時，它可以是 work map 或 minimum SOP 草稿；約三次後條件與 acceptance 已收斂，才考慮升成 Skill。這個順序能避免把一次偶然成功寫死成所有情況的自動做法。

Jimmy 的結論是：有步驟、有驗收的東西是 workflow；它需要獨立入口、owner 和更新，而不是藏在一句個人偏好裡。

用這個階梯判斷：

1. 一次性工作：放在 task card；
2. project 內反覆但未穩：先放 work map／SOP 草稿；
3. 做法與例外開始收斂：寫 minimum SOP；
4. 已能清楚 input、output、acceptance、stop line：才是 Skill 候選。

這樣分後，AI 不是「記住一段很長設定」；而是在適當工作時讀到適當流程，按適當邊界執行。

## 放錯層為何這麼難發現？過期規則不會報錯，但會慢慢令 output 答歪

如果一段過期背景留在 chat，最多是下一次需要重講；若它被錯放進長期偏好或 project 指示，問題更隱蔽。AI 仍會生成合理句子，但它可能用去年格式、錯 project 的限制，或把原本一次性的「不要提價錢」當成永久禁令。你只會覺得 output 有點怪，卻很難追到源頭。

所以 context routing 除了「放進去」，還包括定期看哪些該退休。這不是要你每周整理所有設定，而是每次遇到反覆怪異 output 時，先問是否有舊規則仍活在不該活的層，而不是立刻換工具或重寫所有 prompt。

Jimmy 的結論是：過期 context 的危險不在於它完全錯，而在於它會安靜地把今天的工作拉回昨天。

| 應放層 | 錯放後果 | 首先怎樣修 |
|---|---|---|
| 長期偏好 | 每次留在 task，重講不斷 | 升到 identity／voice note |
| 今次 task | 錯放長期層，舊要求一直生效 | 移出、標失效 |
| Project 規則 | 錯放全局，其他 project 被污染 | 移回 project source of truth |
| Workflow | 錯放偏好，流程只執行一半 | 寫 SOP／Skill 入口 |

每季或每個 project 結束時，只清一小批容易混淆的規則已經足夠。目標不是零設定，而是任何仍影響工作內容的規則都找得到 owner。

## 用公開教學 outline 跑一次：新 AI session 怎樣只讀正確四層 context

以下是 synthetic 示例。假設你要把一篇指定公開文章整理成 internal teaching outline。新 session 不需要讀完整歷史；只需要眼前 task 的文章與 output 格式、你的長期香港廣東話教學語氣、project 的「只用公開材料／未知必標／不可外發」規則，以及已跑穩時才會使用的 review workflow。

這個分法令每層都只承擔它應承擔的東西。AI 能起 draft，但不能把未知寫成事實或直接外發；owner 仍負責確認來源、收貨與處理例外。你同時測到新 session 有沒有真正接到正確 context。

| 層 | 本輪內容 |
|---|---|
| Task | 指定 URL、outline 格式、交 owner review |
| 長期偏好 | 香港廣東話、先講工作摩擦 |
| Project 規則 | 只用公開材料；未知要標；不對外發送 |
| Workflow | 若格式已跑穩，對照固定 acceptance checklist |

Jimmy 的結論是：四層設定法的成果，不是令 AI 永遠記住你，而是令新 session 也能在正確範圍內開始，而不會亂帶歷史規則。

若 output 還是不對，先檢查是哪一層的 input、owner 或更新日期不清；不要把所有舊 chat 一次貼進去。

## 今日十分鐘怎樣開始？只分最近重講最多的五句背景

不要先修改所有工具設定。打開一張空白 note，寫下最近一個月重講最多的五句背景，逐句問：下次同類工作還需不需要？違反是否會出事？它是否已有第一步、第二步？答案會自然指向 task、偏好、project 規則或 workflow。

第一輪只移動一兩句，然後開一個新 session 測試：它能否覆述自己今次可做甚麼、不可做甚麼、誰會收貨？若不能，補最早缺的一層，而不是不斷加長開場白。

Jimmy 的結論是：你不是記性差；你只是需要把不同壽命、不同風險的 context 放回正確層。

今天請做：

1. 寫下五句最常重講背景；
2. 用生命週期把它分到四層；
3. 將一條硬規則改寫成明確 stop line；
4. 把一個有步驟的內容標成 SOP／Skill 候選，不再當偏好；
5. 在新 session 用公開或 synthetic 小任務測試一次。
